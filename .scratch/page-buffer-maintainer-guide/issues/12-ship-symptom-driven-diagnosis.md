# 12: Ship symptom-driven diagnosis

**What to build:** Let a maintainer start from an observed page-buffer symptom and reach the correct state owner, source route, evidence boundary, and next diagnostic or verification action without rereading the learning path.

**Blocked by:** 11: Ship change and verification playbooks

**Status:** ready-for-agent

- [ ] Fix/holder leaks route through acquisition count, nested debt, promotion/ordered transfer, post-grant failures, and request-end diagnostics.
- [ ] Waits are classified as transaction lock, page latch, cold-load serialization, victim pressure, or flush wait before deeper analysis.
- [ ] Residency corruption routes through hash/load ownership, publication, identity recheck, victim removal, provisional cleanup, and bypass I/O.
- [ ] Victim pressure separates eligibility failure from search policy and requires actual pressure evidence.
- [ ] Persistent dirty state routes through re-dirty, completion, WAL, TDE/DWB/write errors, lower-bound restoration, and waiter wakeup.
- [ ] Flush symptoms distinguish log durability, copied-generation completion, and home-page/fsync boundaries.
- [ ] Ordered-access stale pointers route through `page_was_unfixed` and page-local observation reconstruction.
- [ ] Metric symptoms route to increment/read sites and retain approximate-snapshot warnings.
- [ ] Each symptom links to canonical explanations, source routes, verification choices, and relevant uncertainty IDs without copying mutable status.
- [ ] Aggregate validation passes for the diagnosis route.
