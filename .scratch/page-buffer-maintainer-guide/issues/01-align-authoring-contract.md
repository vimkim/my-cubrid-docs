# 01: Align the authoring contract

**What to build:** Establish the authoritative writing and maintenance contract for an English, multi-page page-buffer maintainer guide so every later implementation slice follows the same audience, evidence, navigation, asset, and verification rules.

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] The contract identifies the target maintainer and distinguishes core, advanced, playbook, and reference reading modes.
- [ ] The contract requires English explanatory prose and canonical English source identifiers.
- [ ] The contract preserves the pinned CUBRID source revision and requires revalidation before carrying claims to another revision.
- [ ] The contract defines one canonical explanation per concept and keeps exhaustive evidence outside the learning path.
- [ ] The contract recognizes the complete document set rather than one guide file.
- [ ] The contract defines one root asset seam while allowing nested pages to link back to it.
- [ ] The contract requires document-set-wide Markdown, link, SVG, language, Copyparty, and rendered-image verification.
- [ ] Organization-facing verification guidance uses standard CMake, `ctest`, and project-provided test concepts rather than personal convenience commands.
- [ ] Existing unrelated guidance and worktree changes remain intact.
