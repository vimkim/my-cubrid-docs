# 01: 기존 master 환경에서 서버 시작·실패 후 파이프 종료

**What to build:** master가 이미 실행 중인 격리 환경에서 서버 시작 결과를 수집하는 호출자가 정상·실패 모두 다음 작업으로 진행할 수 있게 한다. 성공한 DB 서버는 계속 동작하고, 백그라운드 stdout·stderr는 기존 오류 로그와 별도의 로그에 보존한다.

**Blocked by:** None (can start immediately).

**Status:** claimed

**Parent:** CBRD-27443 — [합의된 스펙](../spec.md). 착수 전에 전체 스펙의 외부 계약·시험 원칙과 이 티켓에 해당하는 근거를 읽는다.

**Acceptance coverage:** A02, A03, A04(기존 master), A05(exec·로그 열기 실패), A06(최초 서버 생성), A09(생성·이어 쓰기), A10, A11.

- [ ] 현재 작업 소스와 실제 바이너리를 식별하고 기존 격리 probe를 사용해 시작 명령 종료와 EOF 부재를 독립적으로 재현한다. master는 이번 호출자의 파이프·잠금을 보유하지 않는 별도 준비 단계에서 시작한다.
- [ ] 정상 시작 후 stdout만 수집, stderr만 수집, 두 스트림 별도 수집, 합친 수집 모두 종료된다. cat과 rg 호출을 확인하고 시작 명령 자체의 종료 코드를 수집기의 코드와 구분한다.
- [ ] EOF 확인 시 서버와 최초 PL 프로세스는 살아 있으며 SQL·PL 요청이 성공한다. 시작 성공 판정 시점·결과 메시지·종료 코드를 기존대로 유지한다.
- [ ] 기존 오류 로그는 그대로 유지하고, 직접 stdout·stderr 메시지는 별도 로그로 보존한다. 로그 목적지·권한·시작 시도 구분 방식을 기록하며 반복 시작으로 이전 내용을 지우지 않는다.
- [ ] 없는 DB 등 기존 실패에서 원래 호출자에게 나오던 진단과 종료 코드를 유지한다. exec 실패와 별도 로그 열기 실패도 호출자에게 전달하고 실패 자식과 FD를 정리한다.
- [ ] 이번 시작 시도의 진단만 전달하며 이전 시도나 다른 DB의 로그가 섞이지 않는다. 로그 파일이 생성되지 않은 실패도 관측할 수 있다.
- [ ] 최초 서버 생성에서 불필요한 일반 FD와 호출자 잠금 참조를 정리하고, 호출자가 자기 FD를 닫으면 다음 호출자가 잠금을 획득한다. 자식이 호출자의 잠금을 명시적으로 해제하지 않는다.
- [ ] 직접 서버 실행과 동기 관리 명령의 기존 출력·리다이렉션·종료 코드를 보존한다. 필요한 공통부 정리는 동작 보존 변경을 먼저 수행하고 이 티켓의 전체 경로로 검증한다.
- [ ] 재현과 수정본 판정을 지속 가능한 shell 회귀 사례로 남기고 native testkit 결과를 제시한다. 수집 도구가 0으로 끝난 것만으로 제품 통과를 판정하지 않는다.

## Implementation notes

별도 로그의 회전은 04에서 완성한다. 이 티켓은 기존 master 조건의 완결된 시작 경로를 제공하며 전체 스펙 완료를 뜻하지 않는다. 일반 재시작·PL 내부 FD·높은 FD 경계는 03에서 확장한다. 구현에 앞서 부모 스펙의 근거 링크를 통해 생성 경계와 다중 스레드 fork 제약을 확인한다.
