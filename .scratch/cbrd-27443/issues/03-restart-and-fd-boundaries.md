# 03: 서버·PL 재시작과 상속 FD 경계 조건 처리

**What to build:** 일반 서버 자동 재시작과 PL 재시작 뒤에도 호출자 및 부모 내부 자원이 불필요하게 상속되지 않고 SQL·저장 프로시저가 정상 동작하게 한다. 까다로운 FD 배치에서도 같은 계약을 보장한다.

**Blocked by:** 02: master가 없는 환경과 직접 daemon master 시작 처리.

**Status:** ready-for-agent

**Parent:** CBRD-27443 — [합의된 스펙](../spec.md). 착수 전에 전체 스펙의 외부 계약·시험 원칙과 이 티켓에 해당하는 근거를 읽는다.

**Acceptance coverage:** A06, A07, A08, A13; A01–A05와 A11 영향 회귀.

- [ ] master가 초기 호출자 자원을 놓은 상태에서 격리 인스턴스의 일반 서버 자동 재시작을 유발한다. 새 서버와 PL의 생성, SQL·PL 성공, 호출자 파이프·잠금 미보유를 함께 확인한다.
- [ ] 재시작 부모가 실행 중 새로 연 내부 오류 로그·DB 볼륨 등 불필요한 FD도 자식에게 남지 않는지 확인한다. FD 번호뿐 아니라 실제 대상을 비교한다.
- [ ] PL만 재시작해 저장 프로시저 실행이 복구되고 불필요한 부모 내부 FD가 전달되지 않음을 검증한다. SA의 PL 실행과 기존 출력도 보존한다.
- [ ] 같은 파이프의 높은 번호 복제 FD, 높은 FD를 연 뒤 낮아진 soft limit, 이미 닫힌 표준 FD, 큰 FD 한계에서 누락 없이 정리된다. FD 번호 재사용으로 다른 파일에 출력이 기록되지 않는다.
- [ ] 실행 중 전달받는 소켓과 exec를 넘어 보존할 FD를 구분하고, 필요한 통신 및 초기 오류 전달 계약을 유지한다.
- [ ] 다중 스레드 부모의 fork 이후 자식 경로와 플랫폼 fallback을 검토한다. 실행 가능한 오류 조건을 시험해 deadlock, 부모 흐름 복귀, 잔존 실패 자식이 없음을 확인한다.
- [ ] CLI 경계에서 가능한 사례를 우선 검증하고 재현하기 어려운 FD 배치만 프로세스 생성 경계의 보조 시험으로 검사한다. 번호나 함수 호출 순서 자체를 통과 조건으로 삼지 않는다.
- [ ] 수정한 공통부가 영향을 주는 최초 시작·실패·직접 실행·동기 명령을 회귀 검증하고, 각 결과에 실제 커밋과 바이너리를 기록한다.

## Implementation notes

02에서 master 최초 생성과 진단 대상이 정리되어야 master가 부모인 재시작의 새 FD 소유 관계를 검증할 수 있다. 04의 로그 회전 완성은 이 티켓의 선행 조건이 아니다.
