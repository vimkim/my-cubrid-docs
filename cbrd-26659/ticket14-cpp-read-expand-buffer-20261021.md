## Added regression contracts

`OosSqlVisibleVersion.StoredAndExpandedFetchPreserveMixedRowsAndCallerOwnedBytes` creates a single heap with two logical rows. Row 1 has the literal six-byte payload `19 ab 23 cd 45 ef`. Row 2 has 17,001 `a1` bytes, 17,003 `b2` bytes and 17,003 `c3` bytes. The cheap heap scan copies each stored record before any Resolve or Expand. It reads the fixed identifier from that record, requires exactly the two independent IDs, and checks HAS_OOS clear/set for the matching logical row. The stored OOS stub is parsed only after its flag is observed. No grouped Read occurs during this stored scan.

The raw-byte fetch then uses caller-provided COPY storage. It preserves the caller pointer and CHN, clears the materialized HAS_OOS flag, and produces one grouped Read only for the OOS-backed row. After the scan cache ends, an OOS-unaware `OR_BUF` consumer decodes and compares every payload byte to the independent model. A separate PEEK fetch confirms scan-cache ownership for expanded OOS bytes and consumes those bytes before ending the cache. A later cheap fetch proves that materialization did not rewrite stored HAS_OOS or the head OID, length and stamp. The result copy has no physical stored-state transition.

`OosSqlVisibleVersion.ExpandRetryPreservesCallerBufferAndStoredReference` first observes a real stored 64 KiB OOS-backed value. A caller buffer large enough for the stored stub but too small for expansion receives `S_DOESNT_FIT`, a negative required length, the same pointer/capacity and untouched guard bytes beyond capacity. A caller-positioned buffer with zero writable bytes also remains caller-owned. A retry with exactly the reported capacity succeeds without touching its trailing canary. After cache teardown, every `ab` payload byte remains readable. The persisted stub identity remains unchanged after both rejection and success.

These cases use the existing heap fetch, inline-stub parser and raw-record consumer seams. They introduce no observation API, production behavior change, new framework or padding-byte identity oracle.
