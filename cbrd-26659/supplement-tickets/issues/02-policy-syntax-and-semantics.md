**What to build:** 지원/오류 문법과 타입·문맥별 의미 검사, 정책 유지·초기화·변경 및 거부 후 데이터/메타데이터 보존.

**Blocked by:** [01: 기준 리비전·커버리지 확정과 HAS_OOS 관측 tracer](01-baseline-and-record-observer.md)

**Status:** ready-for-agent

기준일: 2026-10-21, Asia/Seoul. 기존 work: Work457, Work458, Work459. Spec user stories: 9, 10, 11, 12, 13, 16.

실행 전 [지도와 공통 완료 규칙](../map.md)을 읽는다. 현행 권한·자원 격리·native 검증 규칙은 모든 사례에 적용한다.

## Acceptance criteria

- [ ] 01의 기존 목록에서 충분한 정책 사례를 재사용하고, 지원 정책의 정상 문법과 누락된 오류 문법을 구분하여 보완한다.
- [ ] 잘못된 토큰·값, 중복·충돌 절, 지원되는 식별자·절 문맥을 검사한다. 문법 거부와 도메인·문맥에 따른 의미 거부를 구분한다.
- [ ] 정책 기본값, 생략, 명시적 초기화, 복사 및 ALTER의 비소급 동작을 승인된 계약으로 검증한다. 과거 정책 이름이나 상수에 의존한 기대값을 그대로 옮기지 않는다.
- [ ] 정책이 저장 표현에 영향을 주는 사례에는 실제 HAS_OOS 상태의 근거를 연결한다. 정책 메타데이터만으로 행 상태를 주장하지 않는다.
- [ ] 거부 전후의 전체 데이터, 정책 및 관련 스키마 메타데이터를 비교하여 부분 변경이 없음을 확인한다.
- [ ] 필요한 정상·오류 사례를 native SQL로 실행한다. SA/CS 차이를 주장할 경우 그 모드의 실행 증거를 별도로 남긴다.
- [ ] 관련 C++ 사례의 실제 assertion을 retain/add/migrate/remove로 판정한다. 삭제는 동일 계약과 실행 모드의 검증된 대체 사례가 있을 때만 수행한다.

## Evidence and handoff

전체 값·상태에 대한 독립 oracle, 정확한 환경 식별자, selected/executed case와 verdict artifact, 관련 C++ disposition 및 다음 티켓이 재사용할 fixture·제약을 남긴다.
필수 실행의 공백은 해결 전까지 완료 조건을 충족하지 않는다. 재현된 엔진 FAIL은 별도 수정에 연결하고 passing coverage에서 제외한다.
