## Observable behavior and SQL/shell boundary

Each developer case needs two independent claims: the intended logical result and evidence that it exercised OOS. Successful SQL and a test name containing “OOS” do not prove placement. Use distinct uncompressed VARBIT patterns for deterministic size and byte equality, calibrating serialized size separately. `DISK_SIZE` returns serialized primitive size at [fetch.c:3850](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/query/fetch.c:3850). For VARBIT the data writer uses integer alignment at [object_primitive.c:13862](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/object/object_primitive.c:13862); [object_representation.h:2340](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/base/object_representation.h:2340) adds a one-byte prefix below 255 bits, otherwise five bytes, adds `ceil(bit_length/8)`, then rounds to four-byte alignment. Payload bytes, `LENGTH`, serialized bytes and total heap-record size are different quantities. Existing VARBIT unit expectations use `LENGTH` as hex-digit count; use equality and `DISK_SIZE` rather than assuming it reports bits.

## Usable OOS-path evidence and limits

`SHOW HEAP OOS` / `SHOW ALL HEAP OOS` are production SQL interfaces, available independently of `CUBRID_UNIT_TEST_ENABLED`; their metadata requires DBA at [show_meta.c:414](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/parser/show_meta.c:414). [heap_oos.cpp:909](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/storage/heap_oos.cpp:909) constructs 14 columns: table name, class OID, heap volume/file/header IDs, `Has_oos_file`, OOS volume/file IDs, user-page count, page size, chunk-record count, summed chunk-record lengths, physical bytes and unused bytes. A fresh heap without OOS has `Has_oos_file=0`, NULL OOS IDs and zero OOS counters; after a provably demoted insert, a file and positive chunk statistics are expected. The four current SHOW cases assert these schemas and arithmetic, including partition output.

These counts describe **physical OOS chunk records**, not logical SQL values or only MVCC-visible rows. `Oos_recs_sumlen` includes the 24-byte header for each chunk; [oos_prepend_header:2038](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/storage/oos_file.cpp:2038) sets that record length. User-page count includes the sticky header page. Physical bytes equal user pages times page size; unused bytes are `max(0, physical_bytes - summed_record_lengths)` and include metadata/other overhead. [oos_get_stats:3834](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/storage/oos_file.cpp:3834) snapshots sectors and conditionally fixes data pages; [3880](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/storage/oos_file.cpp:3880) explicitly permits an undercount when a page is busy or concurrently freed. Therefore one concurrent zero count cannot prove drain, and a low page count cannot prove survivor integrity. Use quiescence, bounded repeated observation, a known positive control and exact survivor-byte checks.

For a fresh, quiescent one-row table with two **unequal**, single-chunk candidate serialized sizes, chosen so exactly one demotion suffices, expected `Oos_num_recs=1` and `Oos_recs_sumlen=chosen_serialized_size+24` can discriminate largest-first or preference ordering. This is stronger than “some OOS exists”; keep the row/DDL/header-size derivation independent of the implementation's old threshold. SHOW does not validate chain ownership or identities, and cannot prove that an unassigned UPDATE reused the original chain: that needs a suitable stable production observation or retained internal coverage.

Optdebug supports OOS DEBUG diagnostics: [CMakeLists.txt:235](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/CMakeLists.txt:235) sets optimized compilation with debug symbols and `CUBRID_OPTDEBUG` without `NDEBUG`; Release separately defines `NDEBUG`. [oos_log.hpp:162](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/storage/oos_log.hpp:162) enables TRACE/DEBUG/INFO when `NDEBUG` is absent, but the default level is DEBUG. Logging appends to installation-global `$CUBRID/log/oos.log` at [87](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/storage/oos_log.hpp:87), with no DB/PID attribution in its header. Isolate the installation or scope a known byte interval with a positive control; existing unrelated log content is not a receipt for the current case.

A historical `oos_insert ... src.size` activation check is **not valid for current ordinary SQL inserts**. The SQL path calls `oos_insert_many` at [heap_oos.cpp:657](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/storage/heap_oos.cpp:657); its single-chunk and multi-chunk paths bypass the scalar `oos_insert` diagnostic at [oos_file.cpp:2092](/home/vimkim/gh/cb/CBRD-26659-oos-testcases-handover/src/storage/oos_file.cpp:2092). DEBUG chunk-delete messages likewise prove a storage call, not correct MVCC eligibility, completed vacuum, or survivor safety. SHOW plus independent logical checks is the current public placement evidence; source-specific diagnostics are supplementary only.

## Priority gaps and what a green result can claim

1. **P0 — aborted UPDATE → vacuum survivor integrity (CBRD-27237 / accepted CBRD-27230).** [OOS-CONTEXT §5](/home/vimkim/gh/cubrid-oos-context/OOS-CONTEXT.md:454) records an actual historical reproduction on `b871ea386` and the disabled regression preserved in local commit `479cd960ec04196c92bf9789b1fc340af9046c2c`. Neither that test name nor any disabled replacement appears in this HEAD. Current forward-walk and unused notify slot make this a current source-conformance risk, without claiming a fresh reproduction. Existing committed-update, snapshot, eager rollback, identity and leaf tests do not close it: the old stub and live row have the same valid identity. Preserve its explicit uncovered status until a correct engine fix and passing regression establish abort safety.
2. **P1 — physical target, smallest profitable value and policy selection.** Current unit suite lacks desired 4,060-byte/unfill-independent trigger/stop coverage. Existing length-only, equal-value and inline test rows can pass without exercising the intended demotion. Require independent record/serialized-size derivation and an OOS placement oracle; do not update expected answers to match the old source gate. Reconcile the newer implemented FORCE_OUTLINE contract explicitly.
3. **P1 — recovery/HA transport and real snapshot concurrency.** Current crash suite proves committed standalone redo through persisted stubs with exact values, which is materially useful; it does not prove uncommitted or mixed redo/undo, server process recovery, HA replay/failover, or real client snapshot coordination. Replica publication/fixup and manually installed server snapshots must retain their stated scope.
4. **P1 — reclaim progress across real restart and observation races.** Internal growth-sweep coverage is substantial, but restart is simulated, and SHOW can undercount busy pages. An external bounded-growth/drain case needs real process restart, eventual quiescence, positive OOS evidence and exact surviving bytes. Zero statistics alone must not certify absence of data loss or leak.
5. **P1 — LOB, raw-consumer utilities and TDE.** Retain locator-heavy copy/retry regression and utility round trips with source independence, including reading destination bytes after source destruction. Current `xlocator_fetch_all` policy is corrected at this HEAD; utility end-to-end coverage still needs evidence. TDE needs encrypted I/O/recovery evidence beyond recovery-index classification.
6. **Explicit deferred gap — CDC/flashback historical images.** ADR-0005 governs current merge scope and supersedes the earlier activation design. Preserve named existing regressions and visible defect disposition; a chosen passing developer pack cannot be reported as CDC historical correctness or used to hide their known failure.
7. **Observation gap — production counters and attribution.** Unit dispatch/seam counters do not exist in a normal optdebug engine; ADR-0001's skip counter is only local TRACE output; installation-global OOS diagnostics lack DB/PID identity. Use public SHOW and isolated logical invariants for current external cases, and identify any behavior that still needs internal-only proof rather than pretending a missing log proves a path was never called.
