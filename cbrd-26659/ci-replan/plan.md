## Test design rules that matter here

- Start with distinguishable, noncompressed VARBIT patterns for size-sensitive tests. Mix patterns within a multi-chunk value so a reordered chain cannot pass by returning identical repeated chunks. Use mixed types in their own type-behavior cases.
- Use whole-value equality as the logical oracle. `DISK_SIZE` and lengths are supporting checks. Derive sizes and expected values before accepting runner output; a `.result` is not automatically a correct `.answer`.
- Prove OOS activation in the same relevant configuration. Product `SHOW HEAP OOS` can establish quiescent per-heap state; it does not directly identify individual attributes, and its conditional-latch scan can undercount busy pages. Placement claims need a discriminating independently derived fixture; reclamation claims need a demonstrated eligible/quiescent state and intact survivors.
- Keep volatile class/file/page IDs out of stable SQL answers. Shell can parse selected diagnostic fields, assert the parse succeeded, normalize IDs and compare the intended invariant.
- The checked SQL grammar/runner provides no portable stable-field `SHOW HEAP OOS` assertion: SHOW is standalone, and ordinary answer comparison retains volatile fields. A delivered shell companion can prove a paired fixture under recorded configuration, but it does not observe the actual public SQL invocation. Credit logical SQL and physical shell evidence separately, with exact fixture/phase/interface differences; do not describe the pair as proof that every public execution demoted values.
- Treat server restart, crash recovery, rollback-after-vacuum and old-snapshot visibility as different behaviors. Immediate rollback success does not cover lifetime after vacuum. No-logging load success does not establish WAL recovery.
- Reuse the repository's case structure, helpers, answer comparison and cleanup. Shell waits have scenario-specific deadlines and an observable condition. Utility exit status and parse success are assertions; empty-string equality, a warning, or a skipped branch does not establish correctness.
- Preserve known failures with intended expectations. Do not silently copy obsolete physical sizes or error numbers, disable an existing regression, or call a defect verified because ordinary CRUD passes.
