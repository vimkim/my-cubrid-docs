# CBRD-26659: contemporary private shell testcase conventions

Created and last modified: 2026-10-12 (Asia/Seoul). Related PRs: engine [8128](https://github.com/CUBRID/cubrid/pull/8128), private TC [4365](https://github.com/CUBRID/cubrid-testcases-private-ex/pull/4365).

Use Bash orchestration, strict `awk` diagnostic readers, validated `jq` fixtures/state, FIFO-driven CSQL sessions, and GNU `timeout`, with a tiny compiled Linux syscall adapter for descendant adoption. The shell/JSON mechanisms have testcase or runtime-source precedents; the syscall adapter supplies a required process capability that Bash cannot set itself. Explicit acknowledgement barriers, exact physical joins, and ownership-preserving cleanup still need bounded custom helpers: the sampled contemporary cases do not provide the complete OOS contract. The accepted [specification](spec.md), [coverage](coverage.md), and delivery reports remain the expectation sources.

## Layout, framework, verdicts, and configuration

The company workflow discovers `*/cases/*.sh` and requires the filename to equal the containing testcase directory. Therefore shared `.sh` libraries can live beside cases or outside `cases` without becoming independent entrypoints when their names do not match. The suite uses private `shell`, CTP `shell -c conf/shell_ci.conf`, and excludes `_25_unstable`. [Workflow discovery contract](https://github.com/CUBRID/cubrid/blob/a5da823b2a84e95b4b22d48abe4a3f9fd601c176/.github/workflows/gha-ci.yml#L191-L200)

Recent examples source `$init_path/init.sh`, call `init test`, use a dedicated database, route failures through `write_nok`, perform cleanup, and call `finish`, including abort paths. CBRD-27484 adds separate setup, positive controls, concurrency, crash detectors, and final cleanup. CBRD-27201 explains why global parameter changes require a dedicated installation and serial execution. [CBRD-27484, 2026-10-02](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/9e9f773d128833aa9e808776ec124ba056bb7bc1/shell/_06_issues/_26_2h/cbrd_27484/cases/cbrd_27484.sh#L56-L109), [CBRD-27201, 2026-09-14](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/4d10dc867ab286c112216c457d1c334590c2c34b/shell/_40_guava/cbrd_27201/cases/cbrd_27201.sh#L11-L53)

The framework owns `cur_path`, `case_name`, `case_no`, and `result_file`; helpers must not overwrite them. `write_ok` and `write_nok` append verdict lines; `write_nok <existing-file>` copies the file's content into the result before cleanup. CTP rejects a blank result. Preserve exact positive verdict counts in native qualification even though CTP also interprets textual results. [Verdict implementation](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/init_path/init.sh#L626-L666), [framework globals](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/init_path/init.sh#L735-L855), [blank-result rejection](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/src/com/navercorp/cubridqa/shell/main/Test.java#L511-L543)

`change_db_parameter` creates `cubrid.conf.org` before modifying configuration; `finish` calls `delete_ini` and `restore_all_conf`. `delete_ini` unconditionally copies that backup, so a case that bypasses the parameter helper still needs its framework backup arranged before `finish`. Framework `init`/`finish` stop services and broadly kill `cub*` processes: use the native runner's contained installation and serialize local DB validation. Case-local cleanup must remain restricted to proven owned resources. [Parameter backup](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/init_path/init.sh#L917-L939), [unconditional restore](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/init_path/init.sh#L960-L967), [finish](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/init_path/init.sh#L1726-L1740)

## SQL output and strict observations

CBRD-27484 checks bounded CSQL command success and absence of `ERROR`, emits `NO_RESULT` for missing numeric output, and requires exactly `sessions × iterations` positive results equal to its independent expected count. It also confirms the parallel path before crediting coverage. CBRD-27486 requires the exact two-value before/after sequence. These are stronger precedents than treating absence of an error string as success. [Command and count checks](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/9e9f773d128833aa9e808776ec124ba056bb7bc1/shell/_06_issues/_26_2h/cbrd_27484/cases/cbrd_27484.sh#L180-L219), [positive control](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/9e9f773d128833aa9e808776ec124ba056bb7bc1/shell/_06_issues/_26_2h/cbrd_27484/cases/cbrd_27484.sh#L135-L154), [exact before/after sequence](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/99c07503e7bcfb0a402a0ba997dce64d831fbb53/shell/_06_issues/_26_2h/cbrd_27486/cases/cbrd_27486.sh#L146-L178)

For deterministic result sets, CBRD-27201 orders rows, removes timing output with `format_csql_output`, and compares the answer through `compare_result_between_files`. That helper uses whitespace-insensitive comparison and can normalize errors; it is not a strict raw-byte or physical-diagnostic parser. Retain the existing independently reviewed SQL/golden expectations. [Recent ordered answer pattern](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/4d10dc867ab286c112216c457d1c334590c2c34b/shell/_40_guava/cbrd_27201/cases/cbrd_27201.sh#L112-L137), [comparison behavior](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/init_path/init.sh#L425-L483), [timing normalization](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/init_path/init.sh#L1121-L1131)

Gap: the sampled numeric readers select the first matching line and do not reject all duplicate or malformed evidence. The OOS `awk` readers must additionally validate required sections, headers, cardinality, identities, and every row used by an assertion; distinguish a verified empty set from missing diagnostic output. Capture command status before parsing, keep stderr separate when it can contain xtrace, and reject failed commands, truncated fields, duplicate identities, missing markers, and unexpected row counts. This is a conversion requirement from the accepted OOS contract, not an established generic framework guarantee.

## Persistent sessions, crash/recovery, and cleanup

CBRD-27120 recovery, added 2026-09-18, uses `mkfifo`, a held writer FD, persistent `csql --no-auto-commit`, `timeout -k 10`, saved child PIDs, and waits. Keeping the FIFO writer open prevents EOF from rolling back the transaction before the crash. Recovery readiness is separate from data correctness; the case additionally requires recovery undo-work evidence and surviving committed rows. [FIFO session](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/3d454776885cd77bac6f78f024f2709a31397709/shell/_40_guava/cbrd_26857/cbrd_27120_recovery/cases/cbrd_27120_recovery.sh#L150-L179), [child status and restart loop](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/3d454776885cd77bac6f78f024f2709a31397709/shell/_40_guava/cbrd_26857/cbrd_27120_recovery/cases/cbrd_27120_recovery.sh#L80-L133), [nonvacuous recovery proof](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/3d454776885cd77bac6f78f024f2709a31397709/shell/_40_guava/cbrd_26857/cbrd_27120_recovery/cases/cbrd_27120_recovery.sh#L188-L242)

The same example still uses fixed sleeps before kills, and its restart polling has an unbounded inner CSQL command. Its `xkill -f` helper selects processes by command-string matching. CBRD-27484 saves child PIDs and uses per-iteration timeouts but does not implement transactional acknowledgement barriers or signal traps. These limitations must not be copied into the stronger reviewed OOS schedule. [Sleep/kill window](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/3d454776885cd77bac6f78f024f2709a31397709/shell/_40_guava/cbrd_26857/cbrd_27120_recovery/cases/cbrd_27120_recovery.sh#L276-L317), [concurrent PID waits](https://github.com/CUBRID/cubrid-testcases-private-ex/blob/9e9f773d128833aa9e808776ec124ba056bb7bc1/shell/_06_issues/_26_2h/cbrd_27484/cases/cbrd_27484.sh#L222-L245), [xkill selection](https://github.com/CUBRID/cubrid-testtools/blob/44e3f97c788ad82091d5b66d728852f3279b1e86/CTP/shell/init_path/init.sh#L1166-L1199)

Retain explicit unique SQL acknowledgements and journals; reject earlier/duplicate markers and SQL errors before advancing. Bound FIFO opens/writes, acknowledgement polling, each CSQL/utility call, controller duration, restart probes, termination, and reap. Save child ownership and process generations before signalling; close writer FDs, TERM then KILL only owned live processes, reap children, and retain logs before removing owned FIFOs/database files. Reserve cleanup time outside the operational deadline. Readiness and kill-point proof must precede independent logical/physical assertions; timeouts and missing acknowledgements are failures.
