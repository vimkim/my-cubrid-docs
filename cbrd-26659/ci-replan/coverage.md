**Proposed** means implement/reuse/strengthen and then validate. **Defect pending** means correct regression expectations are retained without passing-credit; this phase does not fix the engine. **Capability gap** means no currently established SQL/shell mechanism proves the whole invariant. **Deferred/proposed product** means the inventory records it without silently requiring a new unsupported behavior. None of these states means verified coverage.

**Verified logical subset** means the linked delivery records independently reviewed expectations, exact executed identities, a passing native artifact verdict and cleanup. It does not establish physical OOS placement or the whole behavior row. Ticket01's deliberate wrong-answer run also proves that the normal comparison rejects a false total.

**Verified physical subset** additionally requires positive named class/file/chunk observations and the linked fixture's exact physical oracle. Ticket02 verifies its own quiescent CS fixture, owner DROP and survivor safety; its wrong-seven-chunk run proves assertion rejection and failed-case cleanup. Aggregate chunk statistics do not establish per-row chain identity or every representation boundary.

The [public SQL assertion feasibility](public-sql-inventory.md#layout-validation-and-runtime-limits) check found no portable way to select/normalize stable HEAP OOS fields in current golden answers. A delivered shell companion can prove its paired fixture before destructive phases; it is not observation of the actual public SQL run. Link both records and disclose fixture/interface/configuration differences. Logical SQL coverage and physical shell coverage receive separate credit.

## Smallest useful execution grouping to review

Keep the nine historical SQL cases as reusable starting material, then consolidate overlap and add the missing representation, policy, read and schema behaviors. Do not commit to an exact case count before the first SQL tracer confirms normal discovery, answers and physical evidence. The value/comparison portions can remain public SQL; selected physical observers belong in delivered private shell cases when stable SQL answers cannot express them.

The initial private groups are: (1) physical placement/policies and owned-file creation/DROP, (2) committed crash durability and uncommitted undo with separate model outcomes, (3) deterministic MVCC/lifetime scheduling and observable safe reclaim, (4) utility/backup round trips, and (5) TDE attribution/WAL. Ordinary HA replication is the agreed explicit follow-up gap. Cases for a known failing implementation or an unreachable fault/retry schedule retain their intended oracle and disposition; they do not silently join the passing set or disappear from the inventory.

Sharing a setup is useful only when phases remain independently named and asserted. A failed phase stops dependent phases; later independent coverage does not inherit uncertain state. Reuse compact data and a small actual shared helper rather than creating a campaign framework or copying the long historical durability harness into every case.

## Timing evidence and verification boundary

The old nine-case public suite measured about 111.83 seconds **whole** on a historical release/CTP run, while its SQL body sum was 661 milliseconds. The historical durability shell measured about 20/27 seconds whole on release/debug CTP. The reports preserve their exact revisions, contexts and provenance discrepancies. These show that setup can dominate body time; they do not predict current local optdebug/native cost or a company-CI speedup.

Final local validation will enumerate the delivered SQL and shell paths, execute each selected set with the established native runner, verify exact positive executed counts and passing artifact verdicts, prove cleanup and record separate whole-suite elapsed times. Each measured ticket run covers its exact selected cases; none establishes the complete delivered selection's cost. Proposed runtimes are not presented as measurements, and unit tests or historical answers alone receive no verified delivery credit.
