## Finding and recommended scope

Per-worktree instances require a resource bundle, not just a broker-port increment. Source inspection identifies independent TCP/UDP endpoints, SysV shared-memory keys, named Unix sockets, database registries, persistent storage, and installation-relative mutable files. In particular, changing `CUBRID_TMP` does not relocate every mutable path; PL process metadata and broker PID files remain under `$CUBRID/var`. Sources are itemized below.

**Proposed first scope:** Linux, one user, one network/IPC namespace, one private installation/runtime root per instance, HA/manager/gateway/sharding disabled unless explicitly modeled, and all managed lifecycle actions routed through one controller. An instance is an owned runtime bundle that may contain a master, multiple databases, brokers/CAS, and PL processes; a worktree is its source association, not its process identity. Allow multiple instance IDs for a worktree later without changing the resource model.

Keep the user's two public tools if desired: a validator and an observer/controller. Internally, distinguish validation, observation, and atomic allocation. Observation reports what exists; allocation records exclusive intent among participants; startup acquires the real kernel resources. Calling an observer before an independent `cubrid ... start` leaves a race. This distinction follows from the bind and lock semantics discussed below, rather than from any existing CUBRID allocation feature.

## Evidence boundaries

The inventory covers the pinned Linux engine, shipped broker/gateway/shard configuration surfaces, PL, pinned Manager source, and explicitly noted optional HA/controller paths. Arbitrary user JVM options, custom gateway drivers, test runners, external LOB backends, and future source revisions can introduce resources beyond this inventory. “Unknown component or namespace” must therefore be a real validator result, not a claim of global completeness.

Local prior evidence was consulted first: [PL socket-length startup failures](../cbrd-27089/design/ticket04-cleanup-b871ea386-codex.md) and [binary/library identity mismatch](../cbrd-26659/campaign/CBRD-26659-engine-baseline_f4299ac_claude.md). These are earlier experiment reports at other revisions, not new experiments at this HEAD. Their implications are corroborated where possible with current source. Repository domain guidance was reviewed; the existing OOS context does not define this new instance-management domain.

## Configuration resolution and launch identity

The validator must inspect **effective process configuration**, not only files with familiar names. In the engine, an explicit configuration-file argument takes precedence over `CUBRID_CONF_FILE`, otherwise `$CUBRID/conf/cubrid.conf` is used. HA configuration has its own `CUBRID_HA_CONF_FILE` fallback to installation configuration. The parser reads common and DB-specific sections, has SA-specific and HA host/user sections, applies defaults, then parameter environment overrides and tuning, then forced settings. A `CUBRID_` prefix plus uppercased parameter name is looked up; for example the override for `cubrid_port_id` is `CUBRID_CUBRID_PORT_ID`. Sources: [file and final-order resolution](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/base/system_parameter.c#L6305-L6410), [section order](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/base/system_parameter.c#L6817-L6847), [environment override](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/base/system_parameter.c#L7312-L7348).

`stored_procedure_port` is rejected in the common section, so a generated configuration cannot merely dump every setting into `[common]`. Deprecated aliases also exist; normalize aliases or reject contradictory declarations. [PL section restriction](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/base/system_parameter.c#L6774-L6780), [alias mapping](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/base/system_parameter.c#L5598-L5603).

Broker configuration separately resolves an explicit filename, then `CUBRID_BROKER_CONF_FILE`, then the broker/gateway default. `SOURCE_ENV` can modify spawned component environments. Record that file as a configuration dependency and inspect its effective overrides. The existing broker parser checks several duplicate values within its own configuration but does not establish a host-wide registry. [broker file resolution](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/broker/broker_config.c#L1536-L1565), [source environment](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/broker/broker_admin_pub.c#L764-L786), [local checks](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/broker/broker_config.c#L1282-L1368).

Do not invent general `CUBRID_CONF` or `CUBRID_VARDIR` redirects. The examined directory helpers construct `$CUBRID/conf`, `$CUBRID/var`, `$CUBRID/tmp`, and `$CUBRID/log` directly. [directory helpers](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/base/environment_variable.c#L419-L475). A private installation root is therefore a simpler initial supported contract than attempting to share every installation file while overriding a subset of paths.

Proposed launch manifest: stable instance UUID; worktree path and source commit; actual executable, installation and library paths; build profile; configuration-file hashes; sanitized environment; CWD; DB registry hash; enabled component set; normalized resource claims. Record real executable and loaded library identities from the process, not only `cubrid_rel` output. The earlier local [identity experiment](../cbrd-26659/campaign/CBRD-26659-engine-baseline_f4299ac_claude.md) demonstrated that invoking a binary under another installation's library environment can report that library's version. Explicitly configure `CUBRID`, `PATH`, and `LD_LIBRARY_PATH` for each lifecycle/status command; do not log credentials from inherited environments.

## OS conflict model and observation limits

TCP/UDP ports and abstract Unix sockets belong to a network namespace; SysV keys and IDs belong to an IPC namespace; pathname Unix sockets use filesystem names. Therefore a namespace-aware resource key needs more than a port number or pathname string. Different mount-namespace IDs alone do not prove pathname separation: namespaces may expose the same backing filesystem objects. Compare resolved backing identity where possible; otherwise mark the relationship unknown. For the first implementation it is simpler to declare one supported namespace scope and report other scopes as unsupported. [network namespaces](https://man7.org/linux/man-pages/man7/network_namespaces.7.html), [IPC namespaces](https://man7.org/linux/man-pages/man7/ipc_namespaces.7.html), [Unix sockets](https://man7.org/linux/man-pages/man7/unix.7.html).

Linux POSIX SHM normally uses a tmpfs mounted at `/dev/shm`; unlinking removes the name while extant mappings can continue. Inference for an isolation design: a private IPC namespace alone does not establish separate backing storage for these names; inspect or isolate the `/dev/shm` mount too. [POSIX shm_open](https://man7.org/linux/man-pages/man3/shm_open.3.html).

On Linux `sockaddr_un.sun_path` has 108 bytes. Validate the full encoded pathname with room for termination, including the longest generated broker/proxy/PID/DB suffix. The CUBRID environment check permits a TMP directory length up to 96 based on a master-socket suffix; this does not independently prove that longer PL or handshake suffixes fit. Reject truncation and normalize symlinks through existing ancestors. [Linux socket representation](https://man7.org/linux/man-pages/man7/unix.7.html), [CUBRID directory-length check](https://github.com/CUBRID/cubrid/blob/8459255a457d2089dd35bbf1a9c309624c8fed62/src/base/environment_variable.c#L60-L90).

`shmget` accepts a key and returns a distinct shmid; `IPC_CREAT|IPC_EXCL` fails with EEXIST if that key already exists. Maintain both values, owner UID, creation metadata, attachment count and CUBRID evidence. Do not allocate virtual addresses or delete unknown segments simply because the key lies in a preferred range. [shmget](https://man7.org/linux/man-pages/man2/shmget.2.html).

The observer should combine managed manifests, process identities, endpoint tables, filesystem metadata, IPC metadata and scoped CUBRID status output. `/proc/<pid>/net` describes the process's entire network namespace, not that process's sockets; associate socket inodes with `/proc/<pid>/fd`. `/proc/<pid>/environ` is initial execution environment and may be inaccessible, so it cannot reconstruct every effective configuration. `hidepid` can hide other users' processes. [proc net](https://man7.org/linux/man-pages/man5/proc_pid_net.5.html), [proc fd](https://man7.org/linux/man-pages/man5/proc_pid_fd.5.html), [proc environ](https://man7.org/linux/man-pages/man5/proc_pid_environ.5.html), [proc visibility](https://man7.org/linux/man-pages/man5/proc.5.html).

Proposed process identity uses host boot identity, PID-namespace identity, the PID as seen from the observer, and `/proc/<pid>/stat` starttime, with executable identity as corroboration. Preserve the observer's PID view explicitly when crossing namespaces. Never infer live ownership from PID alone. Each snapshot should state capture time, covered UIDs/namespaces, inaccessible resources, and whether an item is managed, externally observed, reserved, apparently stale, or unknown. Missing visibility means **unknown**, not free. [starttime field](https://man7.org/linux/man-pages/man5/proc_pid_stat.5.html).

Useful read-only capture commands for the future implementation are `ss -ltnp`, `ss -lunp`, `ss -xap`, `ipcs -m`, `ps`, and selected `/proc` reads. Status commands must run with the instance's explicit configuration/environment: a bare `cubrid broker status` would examine whichever broker configuration the current shell selects. The tool should preserve metadata rather than assume process-name matching is a complete instance registry.

## Proposed validator and allocation contract

This section is a design proposal, not current CUBRID behavior or an agreed implementation specification.

The validator accepts a normalized manifest plus a timestamped observation/reservation snapshot and returns structured diagnostics: definite conflict, probable conflict, unknown, or no conflict observed within declared scope. Each diagnostic names both resource owners, the effective value, derivation/configuration source, and evidence. Checks include:

1. Parse/range and enabled-component checks; hexadecimal key normalization; aliases and config/env precedence; complete generated pathname byte limits.
2. Cross-role collision checks for all TCP listeners, all UDP listeners and all explicit/derived SysV keys; wildcard/address-family overlap rather than integer-only port comparison.
3. Private registry versus actual storage-path checks; aliases, directory containment, installation-relative writable files, and generated socket names for maximum configured scale.
4. Live resource and outstanding reservation overlap; missing privileges, unknown optional modules, inconsistent process configuration and changed configuration hashes.

A single local controller may protect reservation transactions with a local advisory lock and durable state, or a transactional database with uniqueness constraints. A reservation is a durable application-level promise among participants, not an OS port or SHM allocation. `flock` is advisory and released when its owning descriptors close; an unrelated process can still bind an endpoint. The actual `bind` remains authoritative and can fail with EADDRINUSE after a successful earlier check. [flock](https://man7.org/linux/man-pages/man2/flock.2.html), [bind](https://man7.org/linux/man-pages/man2/bind.2.html).

Proposed lifecycle:

```text
request instance start
  -> resolve and freeze manifest/config hashes
  -> lock allocation ledger; reconcile; validate entire bundle
  -> reserve entire bundle atomically with generation/token; unlock
  -> controller launches exact command with frozen environment
  -> verify descendants, endpoints, SHM and storage identity
  -> mark running, or retain/reconcile partial-start ownership
  -> stop exact owned instance; verify resource release; release reservation
```

Do not reserve ports by binding, closing, then promising they remain available. Stock startup creates its own sockets and shared-memory segments; keeping placeholder resources open would block it unless a supported handoff mechanism were added and verified. Hold the logical bundle reservation during startup, handle kernel acquisition failures, and serialize competing managed starts. A namespace/container alternative can strengthen isolation but changes the implementation and operating model.

Crash recovery needs durable states such as `reserved`, `starting`, `running`, `stopping`, and `recovery_required`, plus operation IDs for idempotent retries. Lease expiration does not authorize killing a process or deleting IPC. A crashed controller may leave healthy children. First reconcile actual ownership; preserve uncertain resources; use generation tokens to reject stale ledger mutations. Tokens fence lifecycle actions only if the launcher enforces them at execution: stock CUBRID does not consume this token, so a stale actor with direct executable access remains outside that guarantee. Config modifications under a running instance should be rejected or modeled as an explicit reconfiguration transaction, not silently adopted.

An agent instruction requiring this controller is a cooperation policy. Enforcing it against arbitrary direct starts requires control over executable access, execution environments, or isolation boundaries. A passive observer cannot provide that guarantee. Apply the managed path consistently to starts, restarts, broker on/add operations, PL/HA/gateway starts, standalone writers and test runners; the exact supported command list is a spec decision.
