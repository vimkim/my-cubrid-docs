11 / FAIR COMPARISON
공정한 비교는 두 질문을 별도 실험으로 답한다
A. 같은 업무·자원에서 누가 빠른가
같은 row 수·payload·키 요청열·SQL 의미 같은 총 메모리·CPU·storage 예산 격리·durability·동시 접속 조건 명시 DB별 실제 데이터·인덱스 footprint 기록
B. 같은 buffer 압력에서 어떻게 동작하는가
DB마다 W/B를 0.25 / 1 / 4로 맞춤 페이지 크기·저장 구조의 차이 기록 부하 의미·locality·동시성은 고정 동일 engine buffer만으로 RAM 공정성을 주장하지 않음
하나의 실행에 두 공정성을 억지로 섞지 않는다. OS cache·총 메모리·실제 footprint를 함께 보고한다.

12 / INTERVAL METRICS
hit / miss는 측정 구간의 카운터 차이로 계산
Δcounter = 측정 종료값 − 측정 시작값
CUBRID / MySQL
miss proxy = Δreads / Δfetches hit proxy = 1 − miss proxy
PostgreSQL
hit = Δhits / (Δhits + Δreads) miss = Δreads / (Δhits + Δreads)
분모 0은 N/A. counter reset·서버 재시작이 있으면 구간을 무효 처리한다. 샘플 hit %를 단순 평균하지 말고, 구간 카운터 합계로 전체 비율을 계산한다.
서로 다른 DB의 counter를 같은 페이지 요청의 정확한 계수로 간주하지 않는다.

15 / POSTGRESQL TRACKING
