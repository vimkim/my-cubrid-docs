용어와 증거 경계

latch
메모리 구조의 짧은 임계구역을 보호한다. transaction lock과 다르다.
SX
보통 reader와 공존하고 다른 modifier와 충돌하는 mode. 제품마다 정확한 호환표가 다르다.
fix/pin/io_ref
frame identity와 allocation lifetime을 붙드는 reference.
FLUSHING
CUBRID의 in-flight/single-flusher·victim 차단 상태. writer-freeze와 동일하지 않다.
direct I/O
cache 경로 선택. async 여부와 별도 축이다.
AIO
submit 반환 뒤 terminal completion이 오는 I/O. request ownership이 필요하다.
zero-copy
이 책에서는 page-buffer snapshot을 생략한다는 좁은 뜻. TDE/DWB/kernel copy까지 0이라는 뜻이 아니다.
overflow OID page
한 B-tree key에 leaf record가 감당할 수 없는 physical OID/MVCC 정보를 저장하는 별도 page. 다음 page VPID 하나로 연결된다.
VPID
volume과 page를 식별하는 CUBRID page identifier. overflow leaf record는 chain head의 VPID를 가진다.
B-tree SX 후보
overflow page를 읽어 공간을 찾는 동안 reader와 공존하고, target에서 WRITE로 전환하려는 미구현 설계안. flush 전용 IO_WRITE_FREEZE와 책임이 다르다.

CUBRID current mode와 file path는 소스 확정이고, 미래 대안의 성능·공정성은 unknown이다. [CUBRID-C001, CUBRID-C009, CUBRID-C014]

known unknowns와 compatibility limit

  • Unknown copy/freeze/AIO의 throughput, writer p99, memory, fairness 우열은 미측정이다. [CUBRID-C014]
  • TDE/DWB/queue-full/cancel/shutdown fault-injection은 future prototype conformance gate다.
  • CUBRID의 current page format과 WAL/DWB layout을 바꾸지 않는 내부 BCB/request 설계까지만 READY 범위다.
  • public SX ABI, on-disk compatibility, timing·performance equivalence, PostgreSQL/MySQL runtime은 보장하지 않는다.

Quiz와 live Grill

  1. Quiz 1: 직접 workload를 실행해 “runtime이 증명한 것/못한 것”을 분리한다. [CUBRID-C006]
  2. Quiz 2: sync/direct/AIO/copy/frame 계약을 고르고, overflow OID의 AS-IS/TO-BE latch 흐름을 직접 그린다. [CUBRID-C016, CUBRID-C017, CUBRID-C018, CUBRID-C020, CUBRID-C021]
  3. Live Grill: owner/lifetime → state machine → durability/error → 정책/성능 → DBMS 비등가 순으로 한 번에 한 질문을 답한다.

숙련의 기준은 “SX가 좋다/싫다”가 아니다. 주어진 I/O mode에서 input owner, 종료 event, writer exclusion, non-reuse ref, single-flusher, WAL, error cleanup을 빠짐없이 말하고 대안의 반증 조건까지 제시하는 것이다. [CUBRID-C013, CUBRID-C014]

Readiness declaration

READY WITHIN DECLARED SCOPE

현행 snapshot flush의 source-level 재구성과, on-disk format을 바꾸지 않는 request-owned freeze module의 기능 계약·total transitions·conformance oracle까지 준비됐다. 대안의 성능 우위, public SX ABI, timing equivalence는 scope 밖이며 Unknown으로 남긴다.

최종 요약

AIO라서 SX가 필요한 것이 아니다. consumer가 읽는 allocation을 terminal event까지 지키고, content·identity·single-I/O·WAL·dirty·cleanup 책임을 빠짐없이 배정해야 한다. 이 책의 Quiz와 이어지는 Live Grill로 그 판단을 직접 설명하면 학습이 완료된다.
