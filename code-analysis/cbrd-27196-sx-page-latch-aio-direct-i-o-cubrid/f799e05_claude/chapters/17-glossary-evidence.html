용어집

용어정의
latch메모리 frame 내용의 물리적 일관성을 지키는 짧은 잠금. 트랜잭션 수명의 lock과 구별된다.
fix / unfixpage를 buffer pool frame에 고정해 참조를 얻는 것 / 반납하는 것 (pgbuf_fix/pgbuf_unfix).
BCBbuffer control block. frame마다 하나, fix 수·latch 상태·dirty 플래그를 보관.
승격 (promotion)READ latch를 쥔 채 WRITE로 올리는 것. CUBRID에서는 실패 기반.
SX (shared-exclusive)여러 READ와 공존하고 다른 SX·WRITE와 배타인 중간 latch mode. InnoDB SX, PG SHARE_EXCLUSIVE가 등가.
upgrade deadlockREAD를 쥔 두 스레드가 서로의 해제를 기다리며 WRITE 승격을 시도할 때 생기는 원형 대기.
flushdirty page를 디스크에 기록하는 것. CUBRID는 사본을 떠서 쓴다.
재더티 (re-dirty)flush 도중 원본 frame에 가해진 새 수정이 DIRTY 플래그를 다시 켜 다음 flush를 예약하는 것.
WALwrite-ahead logging. data page보다 그 수정 로그를 먼저 디스크에 내리는 규칙.
LSAlog sequence address. 로그에서 record의 위치. page마다 마지막 수정 LSA가 새겨진다.
DWBdouble write buffer. 본 위치에 쓰기 전 사본을 별도 파일에 먼저 써 두는 torn-write 보호 장치.
TDEtransparent data encryption. data page 암호화. flush 시 암호화 출력 사본이 필요.
checkpoint복구 시작점을 앞당기기 위해 dirty page들을 디스크에 반영하는 작업.
victim새 page를 올릴 frame을 확보하기 위해 내쫓기는 대상 page.
buffered write / direct I/O / AIOkernel page cache를 거치는 쓰기 / cache를 우회해 사용자 버퍼에서 장치로 직접 가는 쓰기 / 제출과 완료가 분리된 비동기 쓰기.
watcherperfmon 카운터 수집을 켜 두는 관찰자(interval statdump, csql histogram 등).
SMOstructure modification operation. B-tree의 split/merge 같은 구조 변경.
latch coupling자식 page를 잡은 뒤 부모를 곧바로 놓는 하강 방식.

증거 색인

claim 전체 원장은 evidence/claims.jsonl(35건: CUBRID 20, PostgreSQL 7, MySQL 6, 비교 2 — 설계 추론 1건과 미해결 6건 포함)이며, 소스 기반 claim은 파일·심볼·라인·파일 해시로 고정된다. 런타임 기록은 evidence/runs/(빌드 게이트, 실험 관측, 대조·정리까지 22건), 실험 절차는 experiments/experiment-1,2/, 연구 패킷과 JIRA 발췌 사본은 research/에 있다. 요약 매핑은 18장 교육 지도를 보라.

미해결 질문 (known unknowns)

Unknown. 아래 여섯 항목은 미해결 상태 그대로 claim 원장에 kind=unknown으로 등록되어 있다(CUBRID-C016~C020, PG-C007). 각 항목이 왜 미해결인지는 해당 claim의 한계 서술에 있다.

  1. promote 실패율 baseline: 실운영형 동시 워크로드에서의 실측이 없다. 9장 게이트 1의 선행 과제.
  2. 판정 임계값: memcpy CPU 비중·실패율이 "무시 가능"한 경계값은 수치 확보 후 합의 사항 — 이 보고서는 지어내지 않았다.
  3. DWB 경로의 사본 수: SX 직접 flush 시 DWB slot 기록이 사본 1회로 남는지 — dwb_set_data_on_next_slot의 보관 방식 확인 필요.
  4. 다중 page 연속 승격: delete/merge의 3-page 시퀀스에서 SX 획득 순서와 부분 실패 롤백 규칙.
  5. 재귀 SX / FLUSHING_TO_DISK 통합 여부 / watcher(ordered fix) 상호작용: 16장 변경 목록의 조사 항목들.
  6. PostgreSQL 20devel의 최종 형태: 미출시 브랜치라 릴리스 전 변경 가능.

호환성 한계 고지

이 보고서는 개념·행동 수준의 재구현 준비도를 말한다. ABI, on-disk 포맷, 에러 코드 일치, 타이밍, 성능 수치의 호환성은 약속하지 않는다. 성능 개선 폭은 측정 전이며, 모든 "빨라진다" 서술은 구조적 근거의 존재까지만 뜻한다.

준비도 선언

Readiness. READY WITHIN DECLARED SCOPE — 선언된 범위(latch 체계·승격·flush 깔때기의 행동 재구성과 SX 도입 판단 근거) 안에서, 독립 구현자가 소스를 다시 열지 않고 인터페이스 계약(3장·16장), 상태 소유와 수명(3장), 전이와 실패 조건(3·5·8장), 동시성 보호와 획득 순서(7장), 장애 후 재구성(6장), 도입 순서와 적합성 테스트(16장)에 답할 수 있다. 이 선언은 현행 CUBRID 행동의 재구성과 SX 도입 판단 근거의 완결성에 대한 것이다 — SX 자체의 무교착 결론(CUBRID-C015)은 전제·반증 조건이 명시된 설계 추론(Inferred)이지 구현 검증이 아니며, 두 central behavior(현행 승격·현행 flush)의 증거는 모두 Source+Runtime 등급이다. 위 미해결 6건(unknown claim으로 등록)은 범위 밖 또는 후속 조사로 명시되었다.
