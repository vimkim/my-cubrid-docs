3장 — 인터페이스, 자료구조, 상태 전이

학습 목표

latch 체계의 공개 인터페이스(호출자가 지켜야 할 계약), 상태를 담는 자료구조와 그 소유·수명, 그리고 합법/불법 상태 전이를 파악한다. SX 도입 시 "무엇이 바뀌어야 하는가"의 목록이 이 장에서 나온다.

latch mode 정의

Source-confirmed PGBUF_LATCH_MODE는 enum:uint16_t로 NO_LATCH(0), READ(1), WRITE(2), FLUSH(3), INVALID(4) 값을 갖는다 (page_buffer.h:186-197). 이 중 page를 fix할 수 있는 content latch는 READ/WRITE뿐이고, PGBUF_LATCH_FLUSH는 "flush 완료를 기다린다"는 대기열 전용 pseudo-mode다 — 소스 주석: "page can never be fixed with flush latch mode". [CUBRID-C001]

또 하나의 입력 축으로 PGBUF_LATCH_CONDITION(page_buffer.h:198-203)이 있다: UNCONDITIONAL_LATCH(될 때까지 대기)와 CONDITIONAL_LATCH(즉시 실패 허용, nowait). SX를 설계할 때 이 nowait 축이 중요해진다(16장).

상태 자료구조: 64-bit atomic word

BCB(buffer control block — frame마다 하나씩 있는 제어 블록)는 latch 상태 전체를 원자적 64-bit word 하나에 담는다 [CUBRID-C002] (page_buffer.c:499-508):

union pgbuf_atomic_latch_impl {
  uint64_t raw;                    /* CAS 단위 */
  struct {
    PGBUF_LATCH_MODE latch_mode;   /* uint16: 집계 mode — 지금 제일 센 게 뭔가 */
    uint16_t waiter_exists;        /* 대기자 존재 플래그 (공정성 밸브) */
    int32_t fcnt;                  /* 전체 fix 수 — mode 구분 없음 */
  } impl;
};

소유와 수명: 이 word는 BCB가 소유하고, BCB는 buffer pool이 서버 수명 동안 소유한다. page가 교체(victim)되어도 BCB 구조체는 재사용된다. holder(스레드별 fix 기록)는 스레드 로컬 목록으로 관리되며, 각 항목에 perf 전용 힌트 비트(hold_has_read_latch/hold_has_write_latch, page_buffer.c:445-446)가 있지만 이는 통계용이지 권위 있는 mode 기록이 아니다.

핵심 불변식. 이 설계에서 "누가 어떤 mode로 쥐고 있나"는 집계로만 존재한다: latch_mode=READ, fcnt=3은 "READ가 3개"라는 뜻이고, latch_mode=WRITE, fcnt=1(같은 스레드의 재귀 fix면 fcnt>1)은 "한 스레드가 WRITE"라는 뜻이다. READ와 SX가 공존하는 상태는 이 표현으로는 담을 수 없다 — SX 도입 시 상태어 확장이 필요한 이유다(16장).

상태 전이

            fix(READ)                    fix(WRITE)
  NO_LATCH ──────────▶ READ    NO_LATCH ──────────▶ WRITE
     ▲                  │  ▲                          │
     │   마지막 unfix   │  │      promote 성공        │ unfix
     └──────────────────┘  └──── READ ────────────────┘
                                (제자리 또는 unfix-후-첫대기자 경로)

  겹치는 직교 플래그: FLUSHING_TO_DISK (flush 중), DIRTY (수정됨)

그림 설명: NO_LATCH에서 fix(READ)로 READ 상태로, fix(WRITE)로 WRITE 상태로 전이한다. READ에서 promote가 성공하면 WRITE로 전이한다. 마지막 unfix는 NO_LATCH로 돌아간다. DIRTY와 FLUSHING_TO_DISK는 latch mode와 별개로 켜지고 꺼지는 플래그다.

합법 전이: NO_LATCH→READ/WRITE(fix), READ→WRITE(promote — 단 5장의 실패 조건), READ/WRITE→NO_LATCH(마지막 unfix). 불법 전이: WRITE→READ의 제자리 downgrade API는 없고, FLUSH mode로의 fix도 없다. flush 진행은 latch 전이가 아니라 FLUSHING_TO_DISK 플래그로 표현된다 [CUBRID-C007].

이웃 책임과 seam

  • lock-free 빠른 경로: READ fix/unfix에는 BCB mutex를 건너뛰는 CAS 경로가 따로 있다(7장). SX 설계의 최대 제약이 여기서 나온다.
  • 대기열: latch를 못 받은 스레드는 BCB의 대기 목록에 서고, waiter_exists 비트가 빠른 경로에 "새치기 금지"를 알린다.
  • flush 하위 시스템: WAL(로그 선행 기록)과 DWB(torn-write 보호)가 flush 깔때기에 접합된다(6장).

요약

인터페이스는 셋(fix/promote/flush 깔때기), 상태는 64-bit word 하나(집계 mode + fix 수 + 대기자 비트), holder별 mode 기록은 없다. 이 마지막 사실이 SX 도입의 첫 번째 설계 관문이다. 다음 장에서 이 인터페이스들이 B-tree insert라는 실전 workflow에서 어떻게 조합되는지 본다.
