ch07 — 동시성: 누가 어떤 상태를 보호하고, 어떤 창이 열리는가

학습 목표

  • 관련 스레드 역할(vacuum master/worker, 쓰기 트랜잭션)과 각자의 보호 수단을 말할 수 있다.
  • 래치·sysop·MVCCID 게이팅이 보장하는 것/안 하는 것을 구분할 수 있다.
  • 재사용 경쟁 창이 열리고 닫히는 정확한 시점과, 그 폭을 결정하는 요인을 말할 수 있다.

재사용 경쟁 창 (V-8)

텍스트 대안: 재사용 경쟁 창은 1차 삭제가 슬롯을 비우고 그 페이지를 bestspace 에 재등록하는 순간(삭제 sysop 커밋 전) 열리고, 그 블록의 VACUUMED 도장이 영속화되는 순간 닫힌다. 창 안에서 같은 OOS 파일에 들어온 새 값은 tier-1 캐시 우선·최저 빈 슬롯 우선 정책 때문에 방금 비워진 바로 그 슬롯에 앉을 확률이 높다. 창의 폭은 남은 블록 처리 시간 + master 의 도장 처리 지연이 결정하며, 셧다운·크래시는 창을 재기동 이후로 확장한다.

이 창은 이론이 아니다 — 이번 재현에서 pass 1 완주 후에도 도장 지연분(~1.5초, 12,432 레코드 분량)이 창으로 남아 재기동 후 재주행되었고 (CUBRID-C012), 그중 528개의 재사용 슬롯이 실제 피해가 되었다 (CUBRID-C023).

허용/금지 인터리빙

  • 허용(설계 의도): worker 의 체인 삭제와 다른 트랜잭션의 같은 페이지 다른 슬롯 insert — 페이지 W-latch 가 직렬화하고, 결과는 정합.
  • 허용(설계 의도, 그러나 결함의 재료): worker 가 비운 슬롯을 다른 트랜잭션이 재사용 — 공간 회수의 목적 그 자체 (CUBRID-C045).
  • 암묵적으로 금지되어야 했지만 아무도 막지 않는 것: "재주행 예정인 undo image 가 참조하는 슬롯"의 재사용. 이 집합은 어디에도 기록되어 있지 않으므로 막을 방법 자체가 없다 — 금지를 강제하려면 재사용 유예(비용 큼) 또는 재사용을 감지하는 스탬프(권고안)가 필요하다.

기아·교착 관점

이 결함은 교착·기아를 만들지 않는다 — 반대로 모든 참여자가 순조롭게 전진하기 때문에 발생한다. 잠금 순서 위반도, 대기 사이클도 없다. 동시성 버그의 분류로는 race condition 중에서도 "stale reference 재사용"(ABA)이며, 감지 수단이 없어 재현 전에는 무증상이다.

요약

경쟁 창은 삭제 순간 열리고 도장 영속화로 닫히며, 셧다운은 창을 재기동 너머로 늘린다. 어떤 기존 장치의 계약에도 "점유자 신원" 질문이 속하지 않는다. 다음 장에서 마지막 남은 후보 — "WAL/복구가 막아주지 않을까" — 를 정면으로 반박한다.
