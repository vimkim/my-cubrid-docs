ch08 — 내구성과 복구: WAL 은 잘못된 삭제도 성실히 영속화한다

학습 목표

  • OOS 연산의 로깅 형태(RVOOS_INSERT/DELETE)와 복구 핸들러의 대칭을 설명할 수 있다.
  • page LSA 게이트가 정확히 어떤 질문에 답하는지 — 그리고 2차 삭제가 왜 그 질문 밖인지 답할 수 있다.
  • 크래시 매트릭스: 어느 시점의 크래시가 어떤 상태를 남기는지 나열할 수 있다.

OOS 연산의 로깅 형태

OOS 물리 로깅의 대칭 구조 (CUBRID-C032)
연산redoundo복구 의미
RVOOS_INSERT (oos_file.cpp:2115)조립된 레코드 전체 이미지없음(주소만)redo=재삽입, undo=삭제(oos_rv_redo_delete 재사용)

전체-이미지 물리 로깅이라는 사실이 스탬프 설계에 주는 보너스: 청크 헤더에 필드를 추가해도 복구 핸들러는 그대로다 — 이미지 길이만 4B 늘어난다 (CUBRID-C032).

page LSA 게이트 — 정확한 계약과 그 바깥

많은 독자의 첫 반응: "페이지에 LSA 도장이 있는데 왜 이중 적용이 안 막히지?" 게이트의 실제 코드를 보자:

/* log_recovery.c:496-536 — log_rv_fix_page_and_check_redo_is_needed */
rcv_page_ptr = pgbuf_get_lsa (rcv.pgptr);
if (rcv_lsa <= *rcv_page_ptr)
    { /* already applied — skip */ }
...
assert (log_is_in_crash_recovery ());   /* :529 — 이 분기는 crash recovery 전용 */

Source-confirmed — 게이트가 답하는 질문: "이 로그 레코드를 이 페이지에 이미 적용했는가?" — 과거에 결정된 변경의 replay 중복 방지이며, crash recovery 중에만 도달 가능하다고 스스로 assert 한다 (CUBRID-C022).

2차 삭제는 replay 가 아니다. 복구가 끝난 뒤 평시 vacuum 코드가 (페이지가 아니라) 로그의 undo image 를 읽고, 새로운, 더 높은 LSA 의 RVOOS_DELETE 를 append 하는 신규 연산이다. 엔진이 수행하는 모든 LSA 비교를 통과하고, WAL 기계는 이 잘못된 삭제를 다른 정상 변경과 구별할 방법 없이 충실히 영속화한다 — 복구 관점에서 완벽히 일관된, 내용만 틀린 상태.

sysop 과 복구의 상호작용

1차 pass 의 삭제 sysop 이 커밋된 뒤 크래시가 나면? 복구 undo 는 LOG_SYSOP_END 를 만나면 lastparent_lsa 로 건너뛴다(log_recovery.c:4800-4857) — 커밋된 sysop 은 트랜잭션 롤백에서도 안 풀린다. 즉 크래시는 1차 삭제를 되돌려 주지 않는다. 되돌릴 수 있는 것은 크래시 순간 미커밋이던 sysop 하나뿐이고, 그 undo 는 청크를 원래 slotid 에 복원한다(oos_rv_redo_insert → spage_insert_for_recovery) — 슬롯이 그 사이 재점유되었다면 이 복원 자체가 같은 재사용 문제의 abort 쪽 쌍둥이가 된다(블록-sysop 대안이 기각된 이유 중 하나, ch16) (CUBRID-C022).

잘못된 삭제의 내구성

2차 삭제는 정상 연산이므로: RVOOS_DELETE 가 로그에 남고, 페이지에 새 LSA 가 찍히고, 커밋되고, 체크포인트를 넘어 영속화된다. 이후의 어떤 복구도 이를 의심할 데이터가 없다. 백업에도 손상 상태가 그대로 들어간다. 피해 행을 읽을 때에야 Internal error: slot ... is not allocated 로 표면화되며(ch12 관측), 원인 시점과 증상 시점이 분리되어 사후 진단이 곤란하다 (CUBRID-C023).

요약

WAL/복구 기계는 "무엇을 적용했는가"는 완벽히 추적하지만 "그 적용이 옳았는가"는 묻지 않는다 — 물을 데이터가 없기 때문이다. 내구성 계층은 이 결함의 방어선이 아니라 성실한 공범이다. 다음 장에서 정책 층위로 올라가 재사용·게이팅·probe 알고리즘과 heap 의 대칭 해법을 본다.
