ch06 — 핵심 워크플로: 정상 forward-walk, 그리고 2-pass 사고

학습 목표

  • 정상 forward-walk 를 의사코드 수준(분기 포함)으로 재현할 수 있다.
  • 사고 시퀀스 7단계를 시간축 위에서, 각 단계의 근거 코드와 함께 말할 수 있다.
  • 멀티청크 전파·제2 호출부·eager/REMOVE 대비를 설명할 수 있다.

3. 사고 시퀀스 — 2-pass 타임라인 (V-6, 이 책의 대표 그림)

텍스트 대안: 1차 pass 에서 vacuum 은 undo image 의 옛 head OOS OID(V|P|S)로 정당하게 체인을 삭제하고 sysop 을 커밋하지만, start_lsa 는 전진하지 않고 VACUUMED 도장도 영속화되지 못할 수 있다. 그 사이 다른 살아있는 행(R2)의 oos_insert 가 bestspace 를 통해 방금 비워진 같은 슬롯을 재사용하고 커밋한다. 정상 서버 stop 후 재기동하면 vacuum 이 같은 블록을 재주행하며 불변 undo image 에서 같은 주소를 다시 얻고, probe 가 "점유됨"으로 통과시켜 살아있는 R2 의 체인을 삭제한다. 오류도 경고도 없다.

4. 제2 호출부 — 사정거리는 UPDATE 만이 아니다

Source-confirmed — 로컬 문서들은 UPDATE 경로만 기술했지만, 소스에는 forward-walk 호출부가 둘이다: MVCC 갱신의 update_old_home(RVHF_UPDATE_NOTIFY_VACUUM, vacuum.c:3589-3592)과 remove_old_forward(REC_NEWHOME 삭제 — RVHF_DELETE_NEWHOME_NOTIFY_VACUUM, vacuum.c:3724-3731; 생산부 heap_file.c:23714-23720). 두 경로 모두 같은 신원 없는 코드에 도달하므로 결함과 수정의 테스트 매트릭스는 둘 다 포함해야 한다 (CUBRID-C046). (참고: vacuum_oos.cpp:150-151 의 "UPDATE 전용" 주석은 낡았다 — :207-209 의 주석과 코드가 맞다.)

5. 대비 ①: eager 경로는 왜 안전한가

heap_oos_delete_unreferenced(heap_oos.cpp:701-776)는 !is_mvcc_op 연산 (카탈로그 클래스·SA_MODE)에서 행을 지우는 그 heap 연산 안에서 동기적으로 옛 체인을 지운다. 그 순간 대상 OID 가 이 행의 청크임은 실행 문맥이 보장한다 — 재사용이 끼어들 시간 창이 없고, 로그 유도 재실행도 없다. UPDATE 시엔 old∩new head OID 비교(:754-760)로 새 이미지가 여전히 참조하는 체인을 보존한다 — 트리 전체에서 유일한 OOS OID 공유 검사이며, 미래 dedup 의 전제 조건과 같은 모양이다 (CUBRID-C040).

eager 가 동기 실행으로 공짜로 얻는 신원 보장을, 회수를 임의의 나중으로 미루는 vacuum 은 데이터(스탬프) 없이는 얻을 수 없다. "지연"이 이 결함의 필요조건이다.

6. 대비 ②: DELETE(REMOVE) 는 왜 대상이 아닌가

DELETE 로 죽은 행의 회수는 vacuum_heap 의 REMOVE 경로가 수행한다: heap 슬롯 제거와 OOS 삭제가 한 sysop으로 묶이고(within-sysop, vacuum_oos.cpp:399-426), 재시도 시 대상 heap 슬롯의 MVCC 헤더를 다시 읽어 판정을 재유도하므로(mvcc_satisfies_vacuum) 자연 멱등이다. DELETE 는 stub 이 든 레코드가 페이지에 남아 있으므로 "삭제 대상이 자기 몸에 신원을 지닌" 경우다. UPDATE 는 그렇지 않다 — 옛 버전이 페이지에서 사라지고 undo image 에만 남기 때문에 forward-walk 가 필요했고, 그 forward-walk 에만 신원이 없다 (CUBRID-C041).

요약

정상 경로는 건전하고(실증됨), 사고는 다섯 개의 정상 동작이 겹치는 교차점에서만 일어난다. 수리 지점은 다섯 동작 중 4번(probe)의 질문을 바꾸는 것 — 나머지 넷은 각자의 정당성이 있어 바꾸면 다른 것이 부러진다(ch16 대안 검토). 다음 장에서 ③(재사용)이 일어나는 경쟁 창의 정확한 폭을 잰다.
