네 개의 workflow와 전체 분기

VFID(Volume File Identifier)는 CUBRID file을 가리키는 volume ID와 file ID의 묶음입니다. sysop(system operation)은 file/page 내부 변경을 작은 원자 단위로 commit하거나 abort하는 내부 경계입니다.

load_one_value(session_tx, worker_tx, value):
  require session_tx holds BU on target CLASS
  use session BU for worker object-lock lookup redirect

  if bulk_row:
    omit per-row object lock and row INSID      # current optimization

  if value stays inline:
    return INSERT_INLINE                       # fast

  lock(heap_header, WRITE)
  if header.oos_vfid exists:
    vfid = header.oos_vfid
    unfix(heap_header)
    return WRITE_TO_EXISTING_OOS(vfid)          # hit, including wait-then-hit

  begin_sysop()
  mvccid = get_or_allocate_current_mvccid(worker_tx)
  request X on TRANSACTION_KEY(mvccid)          # TT_LOADDB transaction key만 허용
  result = create_oos_file()
  if result failed:
    abort_sysop(); unfix_header(); return ERROR

  tde = get_class_tde_algorithm(header.class_oid)
  if tde lookup failed:
    abort_sysop(); unfix_header(); return ERROR
  if apply_tde_to_file(result.vfid, tde) failed:
    abort_sysop(); unfix_header(); return ERROR

  log_undo(old_heap_header)
  publish(header.oos_vfid = result.vfid)
  log_redo(new_heap_header)
  mark_header_dirty()
  commit_sysop()
  unfix(heap_header)
  return WRITE_TO_NEW_OOS                      # miss success

finish_worker(worker_tx, result):
  if result failed:
    begin_abort(worker_tx)
  else:
    wait_for_batch_order(); begin_commit(worker_tx)
  publish_mvccid_inactive(worker_tx)
  release_instance_class_root_non2pl_holds(worker_tx)
  free_worker_transaction_index()
check_unique_or_fk(observer_tx, candidate):
  while true:
    observation = read_active_insid_and_btree(candidate)
    if observation has no other active inserter:
      return observation.final_result           # fast

    release_page_latches_and_temporary_object_locks()
    wait = request S on TRANSACTION_KEY(observation.insid)
    if wait failed by timeout/deadlock/interrupt:
      return wait.error                         # failure

    full_release_the_S_lock()
    continue                                    # wakeup은 결론이 아님: 처음부터 재검사

BU 획득과 worker lookup redirect

class install request는 connection request thread에서 server_class_installer::locate_class로 들어가 BU_LOCK을 요청합니다. batch worker가 later object lock을 조회하면 thread_p→conn_entry→get_tran_index()를 통해 session transaction의 class BU를 확인합니다.

instance request가 “grant”처럼 돌아와도 worker 소유의 instance lock entry를 만들었다는 뜻이 아닙니다. session BU를 확인해 별도 entry 없이 우회 성공한 것입니다.

self-lock의 acquire와 ensure

MVCCID 첫 assignment API는 error를 직접 반환할 수 없어 self-lock 실패를 best-effort로 기록합니다. 그러나 실제 INSID가 외부에 보이기 전 heap insert/update producer는 logtb_ensure_mvccid_self_lock을 다시 거쳐 오류를 caller에 전달합니다.

unique/FK helper는 active other inserter를 확인한 뒤 leaf·overflow page latch와 필요한 object lock을 놓습니다. 같은 MVCCID에 S를 얻은 직후 full release하고, active 상태와 B-tree root/key를 다시 봅니다.

OOS는 어디에서 transaction 의미를 만나는가?

heap_oos_find_vfid는 heap header의 OOS VFID가 비어 있을 때만 file을 만듭니다. file_create는 candidate VFID가 vacuum의 dropped-file list와 충돌하지 않는지 transaction-relative하게 검사하려고 current MVCCID를 받습니다. row INSID를 쓰기 위한 요청과 목적이 다릅니다.

첫 사용 크기 주의: 고정 PR revision의 layout 코드는 raw DB_PAGESIZE / 4 기준을 사용합니다. 현재 OOS 설계 문맥의 정규 목표는 4,060바이트입니다. 이 차이는 본 잠금 호출 사슬을 바꾸지 않지만, threshold를 일반 규약처럼 단정하면 안 됩니다.
