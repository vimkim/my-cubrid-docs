이 장에서 다시 쓰는 약어

OID는 Object Identifier로 class/row 같은 logical object를 가리키며 메모리 pointer가 아닙니다. tran_index는 현재 server의 transaction table에서 owner를 찾는 칸 번호입니다. SCH_S_LOCK은 schema stability mode, SCH_M_LOCK은 schema modification mode입니다. UPR은 Upgrader Positioning Rule로, 더 강한 mode로 바꾸려다 막힌 holder를 holder queue의 어디에 둘지 정하는 규칙입니다.

OOS는 Out-of-row Overflow Storage입니다. VFID는 Volume File Identifier입니다. sysop은 system operation입니다. PostgreSQL/MySQL 비교에서 쓰는 MDL은 Metadata Lock, trx_t는 InnoDB transaction state object입니다. “transaction-owned”는 owner를, “transaction-resource”는 잠그는 대상의 종류를 답하는 말입니다.

Readiness declaration

READY WITHIN DECLARED SCOPE

이 선언은 “잠금 기초에서 CBRD-27157의 server-side loaddb transaction self-lock 경계까지”를 conceptual·behavioral하게 재구현할 수 있다는 뜻입니다. CUBRID와 drop-in 호환되는 ABI, exact struct layout, on-disk format, timing, performance 또는 전체 recovery를 약속하지 않습니다.

아래 Interface, abstract state, total transitions, pseudocode, configuration, failure/recovery boundary와 conformance tests가 이 선언의 근거입니다. 남은 runtime evidence gap은 Unknown으로 숨기지 않습니다.

3. Initialization, shutdown, abort, restart order

  1. Engine startup: lock hash, resource mutexes, compatibility table과 transaction table을 먼저 사용할 수 있게 합니다. transaction당 기본 local pool 10개와 boot-time hash sizing을 준비합니다. Persistent lock holder를 disk에서 복원하지 않습니다.
  2. Load start: connection/session transaction이 target class의 BU를 얻은 뒤 worker batch를 accept합니다.
  3. Worker start: batch마다 독립 tran_index와 wait policy를 가진 descriptor를 만듭니다.
  4. Steady state: object lookup은 session BU 계약을 확인합니다. worker가 MVCCID를 받으면 같은 transaction resource에 X self-lock을 acquire/ensure합니다.
  5. Worker success: batch order를 지키며 commit합니다. MVCCID를 inactive로 publish한 뒤 instance(transaction self-lock 포함) → class → root class → non-2PL 순으로 hold list를 풀고 transaction index를 free합니다.
  6. Worker error/abort: ordinary OOS/file state를 먼저 abort/cleanup하고 transaction abort로 remaining locks를 정리합니다.
  7. Session shutdown: active worker에 interrupt를 보내고 완료를 기다립니다. load session object 삭제와 BU release를 합치지 않습니다. outer session transaction commit/abort/unregister가 BU를 해제합니다.
  8. Process restart: lock table은 빈 volatile state로 재구축합니다. durable row/log/file state는 CUBRID recovery module이 재구성합니다. historical assert 뒤 OOS file-sector recovery는 이 보고서의 Unknown입니다.

5. Total policy pseudocode

acquire(thread, key, mode, wait_policy):
  require active_transaction(thread.tran_index)
  require valid(key.type, key.value)

  if thread.type == TT_LOADDB and key.type != TRANSACTION:
    return POLICY_ERROR

  resource = lookup_or_create(key)
  lock(resource.mutex)

  existing = find_holder(resource, thread.tran_index)
  if existing != NONE:
    target = convert(existing.granted_mode, mode)
    if target == existing.granted_mode:
      existing.count += 1
      unlock(resource.mutex)
      return GRANTED(existing)
    if compatible(other_holders(resource, existing), target):
      existing.granted_mode = target
      unlock(resource.mutex)
      return CONVERTED(existing)
    if wait_policy == ZERO_WAIT:
      unlock(resource.mutex)
      return TIMEOUT
    existing.blocked_mode = target
    position_by_upgrader_rule(resource, existing)
    unlock(resource.mutex)
    return suspend_and_cleanup_on_failure(existing, wait_policy)

  if compatible(resource.granted_modes, mode)
     and compatible(resource.waiter_modes, mode):
    entry = attach_holder(resource, thread.transaction, mode)
    unlock(resource.mutex)
    return GRANTED(entry)

  if wait_policy == CONDITIONAL or wait_policy.expired:
    discard_temporary_entry()
    unlock(resource.mutex)
    return TIMEOUT_OR_NO_GRANT

  waiter = allocate_waiter_entry(thread.transaction, mode)
  if waiter == NONE:
    unlock(resource.mutex)
    return ALLOCATION_ERROR  # ER_LK_ALLOC_RESOURCE, queue append 전; 제거할 waiter 없음
  append_waiter_tail(resource, waiter)
  unlock(resource.mutex)
  wake_reason = suspend(waiter, wait_policy)

  if wake_reason in {TIMEOUT, DEADLOCK, INTERRUPTED}:
    detach_waiter_from_both_lists(waiter)
    return wake_reason

  return POST_GRANTED(waiter)

assign_and_publish_insid(transaction, record):
  mvccid = get_or_allocate_mvccid(transaction)
  result = ensure_x_self_lock(transaction, mvccid)
  if result != GRANTED:
    return result
  record.insid = mvccid
  return SUCCESS

wait_for_inserter(checker, insid):
  if not is_other_active(insid):
    return RECHECK
  release_page_latches_and_temporary_object_locks()
  result = acquire(checker, TRANSACTION_KEY(insid), S, checker.wait_policy)
  if result != GRANTED:
    return result
  full_release_s_lock(insid)
  return RECHECK_ACTIVE_AND_BTREE

unlock_entry(transaction, entry, full_release):
  resource = entry.resource
  lock(resource.mutex)

  if entry is in resource.waiters:
    later_waiter = entry.next
    detach_and_free_waiter(resource, entry)
    if later_waiter != NONE:
      grant_later_waiters_compatible_with_earlier_waiters(resource, later_waiter)
    else:
      recompute_total_waiters_mode(resource)
    unlock(resource.mutex)
    return

  detach_holder(resource, entry)
  if not full_release and entry.count > 0:
    clear_failed_conversion_and_reposition(entry)
  else:
    lock(transaction.hold_mutex)  # resource mutex가 바깥쪽
    detach_transaction_hold_link(transaction, entry)
    unlock(transaction.hold_mutex)
    free_entry(entry)

  recompute_total_holders_mode(resource)
  if no_holders_waiters_or_non2pl(resource):
    erase_resource_from_hash_while_locked(resource)
    return

  grant_compatible_blocked_holders_from_front(resource)
  grant_compatible_waiter_prefix(resource)
  unlock(resource.mutex)

unlock_all(transaction):
  while transaction.instance_holds:  # transaction self-lock 포함
    unlock_entry(transaction, first_instance_hold(), FULL)
  while transaction.class_holds:
    unlock_entry(transaction, first_class_hold(), FULL)
  if transaction.root_class_hold:
    unlock_entry(transaction, transaction.root_class_hold, FULL)
  remove_all_non2pl_entries(transaction)

finish_transaction(transaction, decision):
  publish_mvccid_inactive(transaction, decision)
  unlock_all(transaction)
  return decision

find_or_create_oos_file(heap):
  latch(heap.header, WRITE, UNCONDITIONAL)
  if heap.header.oos_vfid != NULL:
    result = heap.header.oos_vfid
    unlatch(heap.header)
    return result
  begin_sysop()
  result = create_file_and_apply_tde()
  if result.failed:
    abort_sysop()
    unlatch(heap.header)
    return ERROR
  log_and_publish(heap.header.oos_vfid, result.vfid)
  commit_sysop()
  unlatch(heap.header)
  return result.vfid

관찰 지점과 debugger landmark

  • CUBRID xlock_dump는 transaction self-lock을 inserter MVCCID로 표시합니다. event log의 blocker/blocked 정보도 MVCCID를 표시합니다.
  • generic acquire/wait counters에는 transaction resource가 섞입니다. 별도 self-lock counter는 없습니다.
  • xlock_dump의 allocated size는 LK_ENTRY와 LK_RES 합계이며 hash bucket·transaction table·local pool·wait-for graph를 포함한 총량이 아닙니다.
  • 주요 debugger landmark: lock_internal_perform_lock_object, lock_transaction_mvccid, logtb_acquire_mvccid_self_lock, btree_wait_for_inserter_end, heap_oos_find_vfid, file_create.
  • transaction-resource timeout message가 union의 OID 표현을 사용할 수 있으므로 사용자 메시지 숫자만으로 MVCCID를 식별하지 않습니다. dump/event log와 함께 봅니다.
  • OOS path는 f03-exp3-observer-v2의 ;oos_stats로 직접 관찰했습니다. small은 no OOS file, large는 VFID와 live record 1을 보였습니다. 비정상 Logical data size는 oracle에서 제외합니다.

8. 용어 사전, Evidence index와 Unknowns

Resource key
lock manager가 보호 대상을 구별하는 type+value 주소입니다.
OID
Object Identifier. class나 row 같은 logical object를 가리키며 메모리 pointer가 아닙니다.
tran_index
현재 server transaction table에서 lock owner를 찾는 칸 번호입니다. 영구적인 업무 ID나 MVCCID와 같지 않습니다.
Owner
lock을 보유하고 release 책임이 있는 transaction입니다. 호출 thread나 session과 자동으로 같지 않습니다.
Waiter
같은 resource의 incompatible mode 때문에 grant를 기다리는 transaction입니다.
SCH_S_LOCK
schema definition을 안정적으로 참조하도록 조정하는 schema stability mode입니다. BU와 호환됩니다.
SCH_M_LOCK
schema definition을 변경하는 요청의 schema modification mode입니다. 이 책의 BU experiment에서는 BU holder와 충돌한 waiter mode였습니다.
BU_LOCK
server-side loaddb가 class OID resource에 사용하는 bulk update object-lock mode입니다.
Transaction-owned lock
transaction이 owner여서 해제 책임을 진다는 분류입니다. resource가 꼭 transaction일 필요는 없습니다.
Transaction-resource lock
transaction 식별자를 resource key로 삼는다는 분류입니다. CUBRID의 MVCCID self-lock이 예입니다.
Lock conversion
같은 owner가 같은 resource에 가진 mode를 재요청해 같거나 더 강한 mode로 합치는 과정입니다.
UPR
Upgrader Positioning Rule. 더 강한 mode를 기다리는 blocked holder의 queue 위치를 정하는 규칙입니다. strict FIFO 보장과 같은 말이 아닙니다.
MVCCID
row version writer를 식별하며 transaction self-lock key로도 쓰는 CUBRID identity입니다.
INSID
record version에 적는 inserter MVCCID입니다. current bulk row에서는 생략될 수 있습니다.
Self-lock
inserter가 자기 MVCCID resource에 가진 X lock입니다. observer가 transaction completion을 기다리는 rendezvous입니다.
OOS
Out-of-row Overflow Storage. 큰 variable value를 heap record 밖의 전용 OOS file에 저장하는 CUBRID subsystem입니다.
VFID
Volume File Identifier. volume ID와 file ID로 CUBRID file을 가리키는 값입니다.
sysop
system operation. file/page 내부 변경을 작은 원자 단위로 commit/abort하는 내부 경계입니다.
MDL
MySQL Metadata Lock. table 이름·정의·open 안정성을 조정하는 SQL 계층 잠금입니다.
trx_t
InnoDB transaction state와 lock ownership을 담는 내부 객체입니다.
