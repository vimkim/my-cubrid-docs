이 책의 목표

마지막에 다음 질문에 답할 수 있으면 됩니다. “어떤 resource를, 어느 transaction이, 어떤 mode로, 왜, 언제까지 잡는가?” 이 다섯 질문을 쓰면 이름이 비슷한 lock도 섞이지 않습니다.

범위: 잠금 기초와 CBRD-27157의 loaddb·OOS(Out-of-row Overflow Storage, 큰 값을 heap record 밖의 전용 저장소에 두는 기능) 경로를 다룹니다. OOS 전체 저장 형식, MVCC snapshot 전체, deadlock victim 알고리즘 전체는 다루지 않습니다.

근거 라벨 읽기

  • Source-confirmed: 고정 revision의 source와 file hash로 확인한 사실입니다.
  • Runtime-observed: 표시한 run ID의 stdout·stderr·실행 metadata에서 직접 관찰한 결과입니다.
  • Inferred: Source-confirmed 전제에서 이끌었지만 별도 runtime으로 직접 보지 않은 결론입니다.
  • Unknown: 이 Report Run의 source trace나 실험으로 닫지 못한 질문입니다.
  • Partial analogy: 일부 책임은 닮았지만 resource·owner·lifetime 중 하나 이상이 다른 비교입니다.
  • Equivalent: 표에 적은 좁은 책임과 범위에서는 같은 protocol로 대응한다는 뜻입니다. 제품 전체가 같다는 뜻은 아닙니다.
  • No equivalent: 조사한 고정 source 범위에서 같은 책임·owner·lifetime 조합을 찾지 못했다는 bounded negative입니다.
  • Not applicable: 선언 범위에서 해당하지 않으며, 왜 해당하지 않는지 근거와 함께 밝힌 항목입니다.
