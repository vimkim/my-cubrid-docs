학습 목표와 상황

목표는 네 primitive를 이름이 아니라 보호 상태, owner, lifetime, block 가능성으로 구분하는 것이다. T2가 B-tree leaf에서 T1의 active INSID를 발견한 순간, page를 붙잡은 채 transaction 종료를 기다려도 되는지 판단해 보자.

Source는 LK_RES.res_mutex로 resource list를 보호하고, block 가능한 경로에서 permanent page latch를 든 suspend를 금지하며, MVCC predicate와 old-version traversal을 별도 경로로 둔다. CUBRID-C004 CUBRID-C021 CUBRID-C027

전체 그림

snapshot: visibility predicate로 visible/too-new/old-version 선택
page latch: 현재 page/slot을 physical하게 안전하게 검사
transaction lock: logical owner와 wait queue를 조정
mutex: 위 lock table 자체의 일관성을 보호

long wait 전: page latch와 transient object state release
wakeup 후: page/index fetch와 업무 predicate 재검사

Visibility는 version 판정이다. Latch는 한 page access에만 머문다. Transaction lock wait은 더 길 수 있어 둘 사이에 release/re-fetch 경계가 있다.

일곱 칸 분석법

(protected state, resource key, requested mode, owner,
 lifetime, blocking rule, release/recheck rule)

예를 들어 self-lock S wait은 (unfinished inserter outcome, TRANSACTION(M), S, observer transaction, 한 번의 completion wait, X와 비호환, S full-release 후 B-tree 재검색)이다. 이름 하나로는 이 정보를 복원할 수 없다.

오용 반례와 불변식

  • Latch를 commit까지 보유하면 unrelated page 접근도 멈출 수 있다.
  • Transaction lock을 page access 종료와 함께 풀면 logical exclusion이 사라진다.
  • Resource mutex를 잡은 채 thread를 suspend하면 grant/release가 같은 state를 갱신하지 못한다.
  • Wakeup 뒤 기존 pointer와 predicate를 그대로 신뢰하면 wait 중 변경을 놓친다.

불변식: block 전에 transient physical state를 놓고, grant publication 뒤 깨어나며, 최신 storage state를 다시 얻는다. CUBRID-C010 CUBRID-C027
