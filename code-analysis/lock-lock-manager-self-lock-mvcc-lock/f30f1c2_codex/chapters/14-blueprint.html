학습 목표와 acceptance scenario

목표는 source의 함수 이름을 외우는 것이 아니라 data model, Interface, total transitions, concurrency order, failure/recovery seam, conformance oracle을 구현 순서로 바꾸는 것이다. Acceptance scenario는 T1의 existing-row UPDATE와 unique INSERT가 active인 동안 T2가 plain SELECT, FOR UPDATE, UPDATE, duplicate INSERT를 실행하고, commit/abort 어느 쪽에서도 stale result나 leaked wait가 없어야 한다는 것이다.

Abstract data model

ResourceKey:
  type = ROOT_CLASS | CLASS | INSTANCE | TRANSACTION
  object payload = oid + class_oid
  transaction payload = full MVCCID

Resource:
  key
  total_holders_mode, total_waiters_mode
  holder_list, waiter_list, non2pl_list
  resource_mutex, hash_link, reclamation state

Entry:
  resource link, transaction link, owner tran_index/thread
  granted_mode, blocked_mode, count, wait start/deadline
  class/root association and granule count where applicable

TransactionLocks:
  class_hold_list, instance_and_transaction_hold_list
  current waiting entries, timeout, self_locked_mvccid hint

Key type는 compatibility domain을 나눈다. Resource는 key 중심 lookup, transaction lists는 owner 중심 cleanup을 제공한다. self_locked_mvccid는 optimization hint일 뿐 authoritative ownership은 resource/entry graph다. CUBRID-C001 CUBRID-C004 CUBRID-C030

Symbolic memory bound는 R·sizeof(Resource) + E·sizeof(Entry) + T·sizeof(TransactionLocks) + hash/pool overhead다. Exact allocator bytes는 compatibility promise가 아니다.

Initialization, abort, shutdown, restart

startup:
  initialize compatibility/config inputs
  allocate transaction lock table and resource hash/pools
  initialize synchronization and start deadlock detector

steady-state request/release:
  mutate only under declared resource/transaction protection

transaction commit/abort:
  publish MVCC/outcome terminal state
  release main/sub self-lock and ordinary held entries
  grant-before-wakeup; reclaim empty runtime resources

orderly shutdown:
  stop producers/detector, cancel or drain waiters,
  assert transaction/resource lists quiescent, free pools

crash/restart:
  do not replay ordinary holder/waiter queue
  recover durable row/log outcome, rebuild runtime structures
  reacquire only declared prepared-2PC object-lock exception

WAL/checkpoint/ARIES 내부는 선언 범위 밖이다. 구현 seam은 “durable outcome recovery가 ordinary lock queue replay를 요구하지 않으며, prepared 2PC만 별도 reacquisition contract를 가진다”까지다.

Branch-preserving algorithms

acquire_object(T, oid, class_oid, requested, policy):
  parent = IS if requested at most S else IX
  acquire class parent; on failure return exact error
  find/create typed INSTANCE resource and owner entry
  if re-request: apply conversion table
  if compatible with holders and ordered waiters: grant
  else if policy is ZERO_WAIT: unwind and return not-granted
  else enqueue waiter/conversion, register timeout/WFG,
       release resource mutex, suspend, then return grant/error
  if granule threshold reached: try class escalation with zero wait;
       on success release covered instances, on failure preserve/fail per policy

execute_mvcc(T, operation, candidate):
  PLAIN_SELECT: snapshot predicate; if too new follow previous version
  FOR_UPDATE/UPDATE/DELETE: class IX, conditional row X;
       on conflict release physical state, wait, refetch, re-evaluate
  INSERT: ensure self-lock before INSID; if fast-path precondition fails use row X

wait_for_inserter(T2, M):
  release page/transient object state
  acquire TRANSACTION(M), S; on failure cleanup+propagate
  fully release S, require M terminal, restart index/record search

finish(T1):
  publish main/sub MVCC terminal outcome
  release X(M) and remaining locks; grant-before-wakeup

구현 순서와 dependency seam

  1. Typed key equality/hash와 compatibility/conversion table을 pure tests로 고정한다.
  2. Resource/entry/transaction ownership과 allocation/unwind/reclamation을 만든다.
  3. Acquire/re-request/conversion/no-wait/wait/release total state machine을 구현한다.
  4. Timeout/interrupt/WFG/deadlock daemon과 grant-before-wakeup을 연결한다.
  5. Class intent와 escalation을 올리고 실패 시 기존 grant 보존을 시험한다.
  6. Query/storage seam에 plain read, locked read, DML policy와 re-evaluation을 연결한다.
  7. MVCCID ensure-before-publication, observer S/full-release/restart, completion-before-unlock을 연결한다.
  8. Commit/abort/subtransaction/shutdown/restart/2PC seam과 observability를 붙인다.
  9. 아래 conformance matrix를 destructive fault 없이 실행하고 claims/runtime 경계를 문서화한다.

Readiness declaration

READY WITHIN DECLARED SCOPE. Typed resource/mode model, ownership, total acquire/wait/release transitions, operation-level MVCC policy, MVCCID X/S rendezvous, publication ordering, error/recovery seam과 conformance oracles를 source와 runtime으로 연결했다. 선언 밖의 WAL 전체, ABI/layout, quantitative tuning은 약속하지 않는다.

최종 teach-back

T1이 existing row를 update하고 새 unique key를 insert한 채 active일 때 T2의 네 SQL이 visibility, class/instance locks, MVCCID self-lock을 어떻게 다르게 쓰며 commit/abort 뒤 무엇을 재검사하는지 설명하라. PostgreSQL과 MySQL/InnoDB에서 같은 책임이 어떤 resource로 갈라지는지까지 말할 수 있으면 이 blueprint의 중심을 재구성한 것이다.
