학습 목표와 restart 질문

목표는 request state machine을 process lifecycle과 섞지 않고 startup·normal shutdown·abort·crash/restart를 구분하는 것이다. 서버가 crash했을 때 “holder/waiter queue를 WAL에서 그대로 복원하는가?”와 “prepared 2PC는 무엇이 예외인가?”를 답한다.

Subsystem lifecycle

UNINITIALIZED
  transaction/MVCC table ready
INITIALIZING
  transaction hold table, object hash/freelist, WFG, detector daemon
  returned init error: partial lock_finalize and unwind
RUNNING
  acquire/wait/release, commit/abort, optional 2PC prepare
FINALIZING
  detector daemon, WFG, object structures, transaction hold table
UNINITIALIZED

PROCESS CRASH:
  ordinary resources/entries/queues vanish
  durable database/log recovery occurs outside ordinary queue replay

Normal finalization destroys detector before graph/hash/transaction storage so it cannot access freed state. Higher-level connection quiescing은 이 lock-manager claim 밖이며 shutdown caller가 보장해야 한다. CUBRID-C050 CUBRID-C051

Ordinary self-lock X/S와 waiter queue를 checkpoint/WAL이 replay한다고 말할 근거가 없다. 반대로 “모든 lock은 volatile”도 너무 넓다. Prepare는 lockless-insert OIDs를 object X로 materialize하고 exclusive object locks를 record에 저장해 recovery에서 infinite-wait로 reacquire한다. WAL/checkpoint/ARIES 전체 구현은 scope-excluded다. CUBRID-C060 CUBRID-C069

Commit, abort, prepared ordering

logged local update commit with retain_lock=false:
  complete MVCC
  append commit/unlock record
  unlock transaction locks
  flush log and mark transaction completed

local abort:
  rollback changes
  complete MVCC
  lock_unlock_all

2PC prepare:
  materialize object X for tracked lockless inserts
  serialize exclusive object-lock list
  append and flush prepare record

첫 branch는 logged local update와 retain_lock=false에 한정한다. Read-only/unlogged, retain-lock, non-local 2PC를 같은 order로 일반화하지 않는다. Self-lock X 자체가 prepare record의 lock-list format은 아니다. CUBRID-C059

Error classes를 하나로 합치지 않는다

Allocation, zero-wait conflict, timeout, interrupt, deadlock victim, escalation abort, shutdown은 서로 다른 transition이다. I/O·ENOSPC·page corruption은 ordinary in-memory acquire가 직접 분류하는 error가 아니라 storage/log caller seam이며, transaction abort와 held-lock cleanup으로 연결돼야 한다. Silent retry나 업무상 “not found” 변환은 금지한다.

Memory formula와 scaling limits

T = configured transaction count
E = lock_escalation
B = max(10000, min(T * E * 3 / 1000, 2^23))

memory inventory approximately:
  8B bucket-pointer bytes
  + T * 10 initial local LK_ENTRY pool
  + R_alloc * sizeof(LK_RES)
  + E_alloc * sizeof(LK_ENTRY)
  + T * sizeof(WFG_NODE)
  + edge_capacity * sizeof(WFG_EDGE)
  + 300 victim slots
  + mutex, allocator, auxiliary overhead

Bucket cap은 약 64 MiB지만 전체 RSS cap이 아니다. xlock_dump size도 allocated LK_ENTRY+LK_RES만 포함해 total lock-manager memory가 아니다. Hot resource list는 O(H+W), WFG pair generation은 local O(H²+H·W+W²) worst case로 추론되며 benchmark가 아니다. CUBRID-C062 CUBRID-C065

무엇을 측정할 수 있는가

Generic counters에는 acquisition, conversion, re-request, wait count/time이 있고 transaction-resource self-lock도 같은 path를 지나므로 섞인다. Dedicated self-lock counter는 확인되지 않았다. xlock_dump는 resource type/key, aggregate modes, holders/waiters, settings, allocated counts와 제한된 size를 보여 준다. CUBRID-C066 CUBRID-C067

재현 가능한 measurement procedure

  1. Revision, T, isolation, timeout, escalation, rollback policy, detector interval, stats_on을 기록한다.
  2. Watcher를 workload 전에 붙이거나 startup 전 stats tracking을 명시하고 baseline counters를 잡는다.
  3. Barrier가 있는 bounded sessions로 holder/waiter/release window를 만든다.
  4. Blocked 시점에 한 번의 full xlock_dump로 exact resource/key/modes를 확인한다.
  5. SQL outcome과 counter delta를 함께 수집하고 self-lock이 generic traffic과 섞임을 밝힌다.
  6. Grant/timeout/interrupt/victim을 구분하고 post-clean resource absence를 확인한다.
  7. 여러 번 반복해 distribution을 제시하되 source branch와 runtime frequency를 분리한다.

stats_on default는 false다. Workload 뒤 watcher를 붙이면 target interval을 놓칠 수 있다. Dump는 lock table을 순회·출력하는 observer라 timing을 교란하므로 짧은 wait latency loop에 과도하게 사용하지 않는다. CUBRID-C075

Diagnostic Unknown

Dump/event formatter는 TRANSACTION resource를 MVCCID로 출력하지만 simple-timeout branch는 union의 OID fields를 error arguments로 넘긴다. 이는 source-level discrepancy일 뿐 user-visible defect가 아니다. Finite-timeout self-lock 실험에서 error/event/dump를 함께 보존하기 전까지 Unknown으로 남긴다. CUBRID-C068

Known unknowns와 safe next experiments

  • self-lock 실제 memory/throughput benefit과 hot-MVCCID fan-in latency
  • adversarial conversion starvation freedom
  • full lock-manager RSS와 WFG allocation-failure runtime
  • active waiter가 있는 shutdown의 higher-level quiescing
  • checkpoint/full-disk가 locks를 보유한 transaction caller에 미치는 영향

이 공백은 ordinary runtime lock table이 storage failure를 소유한다는 식으로 채우지 않는다.

복습과 다음 장

Ordinary queues는 volatile이고 restart 때 재초기화되며 prepared object locks만 제한된 durable exception이다. Configuration과 관측 수치를 정확히 해석해야 source 구조를 성능 결과로 오인하지 않는다. 다음 장은 네 central behavior의 actual CUBRID experiments를 검토한다.
