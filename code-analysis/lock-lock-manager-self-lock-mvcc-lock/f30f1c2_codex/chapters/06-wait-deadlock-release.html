학습 목표와 상황

목표는 incompatible request가 어떤 state를 먼저 publish하고, 어떤 mutex를 놓고 잠들며, release가 무엇을 grant한 뒤 깨우는지 설명하는 것이다. T1의 row X 때문에 T2가 기다릴 때 “signal이 먼저인가, ownership 변경이 먼저인가?”를 추적한다.

Wait publication부터 suspend까지

generic acquire under LK_RES.res_mutex
  link waiter or set blocked_mode
  lock waiter thread-entry mutex
  release resource mutex
  lock_suspend
    assert no forbidden permanent page fix
    publish lockwait pointer/start/timeout/WFG state
    atomically increment suspended-waiter count
    suspend and unlock thread entry on condition

Waiter가 먼저 resource graph에 들어간 뒤 thread wait metadata가 공개된다. Resource mutex나 permanent page state를 든 채 sleep하지 않는다. Timeout/WFG 등록은 wait branch의 일부이며, wake 결과가 grant인지 victim/timeout/interrupt인지 분류한다. CUBRID-C010 CUBRID-C055

Runtime-observed: Experiment 2는 한 row의 X holder와 X waiter, holder rollback 뒤 final balance 101이라는 one-way wait/release만 관찰했다. Cycle이 없어 deadlock detector나 victim selection을 runtime으로 검증하지 않았다. raw dump. CUBRID-C041

Grant-before-wakeup

unlock under resource mutex:
  remove/downgrade releasing holder, recompute aggregate
  grant compatible blocked holders
  scan waiters from queue head; stop at first incompatible request
  unlink each grantable waiter, link as holder, update transaction list
  lock waiter thread-entry mutex
  clear lockwait and publish LOCK_RESUMED
  signal condition, then unlock thread entry

Woken thread가 lock을 “다시 시도”해 얻는 것이 아니다. Resource ownership이 먼저 바뀌고 resume state가 publish된 뒤 signal을 받는다. SQL predicate나 index condition은 별도 caller가 재검사한다. CUBRID-C056

Timeout과 detector daemon

Daemon은 100 ms cadence로 finite timeout과 interrupt를 확인한다. Restart가 끝나지 않았거나 suspended waiters가 2명 미만이거나 configured deadlock interval이 지나지 않았으면 WFG build를 건너뛴다. Default lock timeout은 infinite이고 detector interval default는 1.0초, minimum은 0.1초다. 100 ms loop와 1.0초 interval은 각각 polling cadence와 expensive detection guard다. CUBRID-C057

WFG build와 stale-edge defense

build edges from:
  incompatible holder versus blocked conversion
  holder versus waiter
  preceding incompatible waiter ordering
validate wait timestamp, sequence, current transaction activity
for each cycle:
  choose active-holder victim by priority, logged-work proxy,
  timeout possibility, transaction age
if repeated cycles find no victim and all handlers sleep:
  force one timeout for progress

Timeout은 cycle 없이 한 request를 끝낼 수 있고 deadlock은 validated cycle에서 transaction victim을 고른다. Edge snapshot은 live wait timestamp/sequence로 재검증한다. Victim tie-break 전체와 distributed deadlock은 선언 범위 밖이다. CUBRID-C011 CUBRID-C058

같은 transaction의 여러 worker race

같은 transaction·resource에서 이미 기다리는 thread가 있으면 duplicate entry를 enqueue하지 않고 wait train에 join한다. Join 중 lead waiter가 이미 깨어났으면 resource mutex를 놓고 FIND_RESOURCE부터 다시 시작하며, lead wake는 followers도 깨운다. CUBRID-C064

Victim transaction의 한 rollback owner

Victim transaction에 여러 waiting threads가 있어도 첫 thread만 LOCK_RESUMED_ABORTED_FIRST를 받아 rollback을 주도한다. 나머지는 LOCK_RESUMED_ABORTED_OTHER로 error/cleanup path를 따른다. 여러 worker가 같은 transaction abort를 중복 구동하는 것을 막는다. CUBRID-C072

Fairness mechanism과 starvation Unknown

New requester는 preceding waiter aggregate와도 호환돼야 하고 release grant는 queue head에서 첫 incompatible request에 멈추며 blocked upgrade는 Upgrader Positioning Rule을 따른다. 이 규칙은 overtaking을 제한하지만 adversarial arrivals에서 모든 conversion이 끝난다는 starvation-free proof는 아니다. CUBRID-C074

Early release와 isolation policy

Ordinary early-release는 모든 lock을 자유롭게 버리지 않는다. Force가 아니면 non-shared write locks를 남기고 SERIALIZABLE/REPEATABLE READ는 shared locks를 보존한다. READ COMMITTED는 shared instance lock을 풀 수 있지만 upper-level intention coverage는 유지한다. Transaction end는 instance, class, root, non-2PL lists를 정해진 순서로 정리한다. CUBRID-C071

Hot-resource cost

H holders와 W waiters가 한 key에 모이면 edge build의 pair loops에서 O(H² + H·W + W²) local cost가 가능하다고 추론된다. Hash lookup이 O(1)에 가까워도 fan-in 이후 list/graph work는 싸지 않을 수 있다. 이는 benchmark가 아니라 source-structure bound다.

복습과 다음 장

Wait는 enqueue/publication 뒤 suspend하고, release는 grant를 먼저 publish한 뒤 깨운다. Timeout과 deadlock victim은 다른 종료다. 다음 장은 이 lifecycle을 SQL의 MVCC visibility와 row/class policy에 연결한다.
