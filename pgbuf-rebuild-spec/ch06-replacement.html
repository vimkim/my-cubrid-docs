6장 — 교체 정책 (Replacement Policy)

기준 소스: CUBRID 5cd4f860e · src/storage/page_buffer.c

이 장의 범위 BCB가 어느 리스트의 어느 위치에 놓이는가를 결정하는 모든 규칙 — 3-zone 모델, 리스트 링크 연산 5종, zone 임계 조정, 신규 페이지의 최초 배정, private/shared 리스트 배정 인프라, private→shared 이사, quota 조정 알고리즘, AOUT ghost list — 를 규정한다. 어느 BCB를 실제로 뽑아낼 것인가(victim 선택)는 7장의 몫이다. 이 장의 함수들은 대부분 unfix 경로(5장 §7.1)의 zone 디스패치에서 호출된다.

6.1 zone 모델 — 규범

6.1.1 세 zone의 의미

모든 LRU 리스트는 하나의 이중 연결 리스트이며, bottom_1·bottom_2 두 개의 경계 포인터로 세 구간(zone)으로 논리 분할된다. zone은 별도의 리스트가 아니라 BCB flags 워드에 인코딩된 라벨이다(비트 배치는 3장 §2.2 참조). 설계 의도는 소스 주석에 명시되어 있다 page_buffer.c:188-196.

zone역할victim 가능unfix 시 정책
zone 1
PGBUF_LRU_1_ZONE		 가장 뜨거운 구간. 대부분의 fix/unfix가 여기서 일어난다. 불가 아무 조작도 하지 않는다. 리스트 mutex를 잡지 않는 것이 목적이다.

  • MUST zone 2의 BCB는 PGBUF_IS_BCB_OLD_ENOUGH가 참일 때만 boost한다 page_buffer.c:6746-6750.
  • MUST zone 3의 BCB는 조건 없이 boost한다 page_buffer.c:6791.
  • MUST 위 세 경로 모두 PGBUF_SHOULD_IGNORE_UNFIX(vacuum 워커이거나 temp 볼륨 페이지)일 때는 어떤 이동도 hit 등록도 하지 않는다 page_buffer.c:282-293, 6703, 6732, 6767. 단 zone 3에서는 대신 direct victim 기증을 시도한다(7장 §7.6).

6.1.2 나이 판정 — PGBUF_IS_BCB_OLD_ENOUGH

“충분히 늙었다”는 절대 시간이 아니라 리스트 tick의 상대 경과로 정의된다. 리스트는 top/middle 삽입이 일어날 때마다 tick_list를 1 올리고, BCB는 삽입 시점의 tick을 tick_lru_list에 박아둔다. 즉 “나이”는 내가 들어온 뒤 이 리스트에 새로 들어온 BCB 수다. 임계는 count_lru2 / 2, 즉 zone 2 크기의 절반이다 page_buffer.c:1004-1009.

/* tick은 [0, DB_INT32_MAX) 범위를 순환한다. 뺄셈이 아니라 랩어라운드를 고려한 차이를 쓴다. */
int PGBUF_AGE_DIFF (int bcb_age, int list_age)
{
  if (list_age >= bcb_age)
    return list_age - bcb_age;              /* 정상 구간 */
  else
    return DB_INT32_MAX - (bcb_age - list_age);   /* list_age가 한 바퀴 돈 경우 */
}

bool PGBUF_IS_BCB_OLD_ENOUGH (PGBUF_BCB *bcb, PGBUF_LRU_LIST *list)
{
  return PGBUF_AGE_DIFF (bcb->tick_lru_list, list->tick_list) >= (list->count_lru2 / 2);
}
규범 N6-2 — tick 랩어라운드 MUST tick_list와 tick_lru3는 증가 후 DB_INT32_MAX 이상이 되면 0으로 되돌린다 page_buffer.c:9680-9683, 9768-9771, 10058-10061. 나이 비교는 반드시 PGBUF_AGE_DIFF 형태의 랩어라운드-안전 차이로 해야 하며, 단순 뺄셈을 쓰면 랩 직후 모든 BCB가 “매우 늙음”으로 오판된다.
MUST tick_list는 top 삽입과 middle 삽입에서만 증가한다. bottom 삽입은 tick_list를 건드리지 않는다 page_buffer.c:9784-9823.

이 판정은 두 곳에서 쓰인다: zone 2 boost 조건 page_buffer.c:6746, 그리고 private→shared 이사 조건 2 page_buffer.c:6976.

6.2 리스트 연산 5종

여기 다섯 개는 모두 호출자가 리스트 mutex를 이미 쥐고 있다고 가정하는 내부 프리미티브다. 락 획득·tick 스탬프·zone 재조정은 §6.2.6의 공개 래퍼가 담당한다.

6.2.1 pgbuf_lru_add_bcb_to_top page_buffer.c:9646-9686

/* 전제: 호출자가 lru_list->mutex 보유. bcb는 어떤 LRU에도 속하지 않음(VOID/INVALID zone). */
void pgbuf_lru_add_bcb_to_top (bcb, lru_list)
{
  bcb->prev_BCB = NULL;

6.2.2 pgbuf_lru_add_bcb_to_middle page_buffer.c:9696-9774

“middle”은 bottom_1의 바로 다음, 즉 zone 2의 머리다. zone 1이 비어 있으면 삽입 지점이 없으므로 top으로 대체되지만, zone 라벨은 여전히 zone 2다 — 이 예외를 빠뜨리면 빈 zone 1 상태에서 링크가 끊긴다.

{
  if (lru_list->bottom_1 == NULL)          /* --- 예외 경로: zone 1이 비었다 --- */

          assert (lru_list->bottom == NULL);
          lru_list->top = lru_list->bottom = bcb;
          bcb->prev_BCB = bcb->next_BCB = NULL;

          bcb->next_BCB = lru_list->top;
          bcb->prev_BCB = NULL;

      bcb->next_BCB = bcb_next;

6.2.4 pgbuf_remove_from_lru_list page_buffer.c:10303-10357

경계 포인터 4종(top, bottom, bottom_1, bottom_2)을 모두 보수해야 한다. bottom_2만 규칙이 다르다 — 이전 BCB가 zone 2가 아니면 zone 2가 비었다는 뜻이므로 NULL로 만든다.

/* 전제: 호출자가 lru_list->mutex 보유 (MUST). */
void pgbuf_remove_from_lru_list (bcb, lru_list)
{
  if (lru_list->top == bcb)      lru_list->top = bcb->next_BCB;
  if (lru_list->bottom == bcb)   lru_list->bottom = bcb->prev_BCB;
  if (lru_list->bottom_1 == bcb) lru_list->bottom_1 = bcb->prev_BCB;

  if (lru_list->bottom_2 == bcb)
    {
      if (bcb->prev_BCB != NULL && pgbuf_bcb_get_zone (bcb->prev_BCB) == PGBUF_LRU_2_ZONE)
        lru_list->bottom_2 = bcb->prev_BCB;
      else
        { assert (lru_list->count_lru2 == 1); lru_list->bottom_2 = NULL; }
    }

  if (bcb->next_BCB != NULL) bcb->next_BCB->prev_BCB = bcb->prev_BCB;
  bcb_prev = bcb->prev_BCB;
  if (bcb_prev != NULL)      bcb_prev->next_BCB = bcb->next_BCB;

  bcb->prev_BCB = bcb->next_BCB = NULL;

  /* 순서가 중요하다: 링크를 끊은 "뒤에" hint를 전진시킨다. 끊기 전에 바꾸면
   * 다른 스레드가 이 bcb를 hint로 재설정할 수 있다. */
  pgbuf_lru_advance_victim_hint (lru_list, /*prev_hint*/ bcb, /*new_hint*/ bcb_prev, false);

  pgbuf_bcb_change_zone (bcb, 0, PGBUF_VOID_ZONE);   /* zone 카운터 감소 + 후보 해제 */
}

6.2.5 pgbuf_lru_boost_bcb page_buffer.c:10072-10137

/* 전제: 호출자는 bcb mutex를 보유하고 있고, 리스트 mutex는 이 함수가 잡는다.
 * assert: zone != PGBUF_LRU_1_ZONE (zone 1 boost는 호출 전에 걸러져야 한다) */
void pgbuf_lru_boost_bcb (bcb)
{
  lru_list   = pgbuf_lru_list_from_bcb (bcb);
  zone       = pgbuf_bcb_get_zone (bcb);
  is_private = PGBUF_IS_PRIVATE_LRU_INDEX (lru_list->index);

  assert (zone != PGBUF_LRU_1_ZONE);

  /* 1) 통계를 "먼저" 올린다 (락 밖) */
  if (zone == PGBUF_LRU_2_ZONE)
    perfmon_inc (is_private ? PSTAT_PB_UNFIX_LRU_TWO_PRV_TO_TOP
                            : PSTAT_PB_UNFIX_LRU_TWO_SHR_TO_TOP);
  else /* zone 3 */
    perfmon_inc (is_private ? PSTAT_PB_UNFIX_LRU_THREE_PRV_TO_TOP
                            : PSTAT_PB_UNFIX_LRU_THREE_SHR_TO_TOP);

  pthread_mutex_lock (&lru_list->mutex);          /* ← 리스트 락 획득 */

  pgbuf_remove_from_lru_list (bcb, lru_list);      /* 2) 현재 위치에서 제거 */
  pgbuf_lru_add_bcb_to_top (bcb, lru_list);        /* 3) top에 삽입 (zone := 1, tick_list++) */

  /* 4) zone 1이 커졌으므로 임계를 다시 맞춘다 */
  if (zone == PGBUF_LRU_2_ZONE)
    pgbuf_lru_adjust_zone1 (lru_list, /*min_one*/ true);   /* 2→1 이동뿐이므로 zone 1만 */
  else
    pgbuf_lru_adjust_zones (lru_list, /*min_one*/ true);   /* 3→1 이동이므로 전체 */

  pgbuf_lru_sanity_check (lru_list);               /* 디버그 빌드 전용 */
  pthread_mutex_unlock (&lru_list->mutex);
}

6.3 zone 임계 조정

6.3.1 pgbuf_lru_adjust_zone1 page_buffer.c:9833-9876

/* zone 1이 임계를 넘으면 바닥부터 위로 올라가며 라벨을 1→2로 바꾼다. 링크는 건드리지 않는다. */
void pgbuf_lru_adjust_zone1 (lru_list, bool min_one)
{
  threshold = lru_list->threshold_lru1;
  if (min_one) threshold = MAX (1, threshold);
  if (threshold >= lru_list->count_lru1) return;      /* 조정 불필요 */

  /* zone 2가 비어 있었다면, 강등될 첫 BCB(현재 bottom_1)가 곧 zone 2의 바닥이 된다 */
  if (lru_list->bottom_2 == NULL)
    lru_list->bottom_2 = lru_list->bottom_1;

  for (b = lru_list->bottom_1; threshold < lru_list->count_lru1; b = b->prev_BCB)
    pgbuf_bcb_change_zone (b, lru_list->index, PGBUF_LRU_2_ZONE);  /* count_lru1--, count_lru2++ */

  /* 루프는 마지막 강등 뒤 b를 prev로 한 칸 더 옮겨 놓았다 ⇒ b가 새 bottom_1 */
  lru_list->bottom_1 = (lru_list->count_lru1 == 0) ? NULL : b;
}

6.3.2 pgbuf_lru_adjust_zone2 page_buffer.c:9886-9926

void pgbuf_lru_adjust_zone2 (lru_list, bool min_one)
{
  threshold = lru_list->threshold_lru2;
  if (min_one) threshold = MAX (1, threshold);
  if (threshold >= lru_list->count_lru2) return;

  for (b = lru_list->bottom_2; threshold < lru_list->count_lru2; b = b_prev)

}

6.3.3 pgbuf_lru_adjust_zones page_buffer.c:9936-9992

2단계다: 먼저 zone 1+2 합계의 초과분을 zone 3으로 떨어뜨리고, 그 다음 zone 1 내부 임계를 맞춘다.

void pgbuf_lru_adjust_zones (lru_list, bool min_one)
{
  threshold = lru_list->threshold_lru1 + lru_list->threshold_lru2;
  if (min_one) threshold = MAX (1, threshold);

  if (threshold >= PGBUF_LRU_ZONE_ONE_TWO_COUNT (lru_list))
    {
      pgbuf_lru_adjust_zone1 (lru_list, min_one);   /* 합계는 괜찮다. zone 1만 손본다 */
      return;
    }

  /* 바닥에서 시작: zone 2가 있으면 bottom_2, 없으면 bottom_1 */
  for (b = (lru_list->bottom_2 != NULL ? lru_list->bottom_2 : lru_list->bottom_1);
       threshold < PGBUF_LRU_ZONE_ONE_TWO_COUNT (lru_list); b = b_prev)
    {
      b_prev = b->prev_BCB;
      pgbuf_lru_fall_bcb_to_zone_3 (b, lru_list);
    }

  if (lru_list->count_lru2 == 0)
    {
      lru_list->bottom_2 = NULL;
      lru_list->bottom_1 = (lru_list->count_lru1 == 0) ? NULL : b;
    }
  else
    {
      lru_list->bottom_2 = b;
    }

  pgbuf_lru_sanity_check (lru_list);
  pgbuf_lru_adjust_zone1 (lru_list, min_one);       /* 2단계: zone 1 내부 임계 */
}
min_one의 의미 min_one = true면 임계를 MAX(1, threshold)로 올려, zone 1과 zone 2가 완전히 비지는 않도록 보장한다 page_buffer.c:9945-9948, 9840-9843, 9894-9897. quota가 0인 private 리스트에 false로 호출하면 zone 1·2가 실제로 0이 되어 리스트 전체가 victim 구간이 된다 — 이것이 §6.7 8단계의 “무활동 리스트 회수” 메커니즘이다.

6.3.4 pgbuf_lru_fall_bcb_to_zone_3 page_buffer.c:10002-10063

zone 3으로 떨어지는 순간은 BCB가 처음으로 교체 가능해지는 순간이다. 그래서 리스트에 넣기 전에 먼저 대기 중인 스레드에게 직접 기증(direct victim, 7장 §7.6)을 시도한다.

6.4 신규 페이지의 최초 배정

디스크에서 막 읽어온 BCB는 PGBUF_VOID_ZONE 상태이며 어느 리스트에도 속하지 않는다 (invalid list에서 꺼낼 때 page_buffer.c:8891, 또는 교체를 위해 리스트에서 뺄 때 10356). 리스트에 들어가는 시점은 첫 unfix다.

6.4.1 pgbuf_unlatch_void_zone_bcb 결정 트리 page_buffer.c:6844-6939

/* 전제: 호출자가 bcb mutex 보유. zone == PGBUF_VOID_ZONE.
 * thread_private_lru_index: 이 스레드의 private LRU 인덱스, 없으면 -1 */
void pgbuf_unlatch_void_zone_bcb (bcb, int thread_private_lru_index)
{
  bool aout_enabled = false;
  int  aout_list_id = PGBUF_AOUT_NOT_FOUND;   /* = -2 */

  /* ── 1단계: AOUT 조회 (조회가 곧 제거다) ───────────────────────── */
  if (pgbuf_Pool.buf_AOUT_list.max_count > 0)
    {
      aout_enabled = true;
      aout_list_id = pgbuf_remove_vpid_from_aout_list (&bcb->vpid);
    }

  /* ── 2단계: vacuum 워커 분기 ────────────────────────────────── */
  if (PGBUF_VACUUM_SHOULD_IGNORE_UNFIX (thread_p))
    {
      perfmon_inc (aout_list_id == PGBUF_AOUT_NOT_FOUND
                     ? PSTAT_PB_UNFIX_VOID_AOUT_NOT_FOUND_VAC
                     : PSTAT_PB_UNFIX_VOID_AOUT_FOUND_VAC);

      /* 대기자에게 바로 넘길 수 있으면 리스트에 넣지 않는다 */
      if (!pgbuf_bcb_avoid_victim (bcb) && pgbuf_assign_direct_victim (bcb))
        {
          perfmon_inc (PSTAT_PB_VICTIM_ASSIGN_DIRECT_VACUUM_VOID);   /* 상세 통계 시 */
          if (pgbuf_Pool.buf_AOUT_list.max_count > 0)
            pgbuf_add_vpid_to_aout_list (&bcb->vpid, aout_list_id);
          return;                              /* 어떤 리스트에도 들어가지 않는다 */
        }
      aout_list_id = PGBUF_AOUT_NOT_FOUND;     /* 기증 실패: AOUT 결과를 무효화 */
    }
  else
    {
      perfmon_inc (aout_list_id == PGBUF_AOUT_NOT_FOUND
                     ? PSTAT_PB_UNFIX_VOID_AOUT_NOT_FOUND
                     : PSTAT_PB_UNFIX_VOID_AOUT_FOUND);
    }

  /* ── 3단계: private 리스트가 있는 스레드 ──────────────────────── */
  if (thread_private_lru_index != -1)
    {
      if (PGBUF_VACUUM_SHOULD_IGNORE_UNFIX (thread_p))
        {                                       /* vacuum: 무조건 private TOP */
          pgbuf_lru_add_new_bcb_to_top (bcb, thread_private_lru_index);
          perfmon_inc (PSTAT_PB_UNFIX_VOID_TO_PRIVATE_TOP_VAC);
          return;                               /* hit 등록 없음 */
        }

      if (!aout_enabled || thread_private_lru_index == aout_list_id)
        {                                       /* AOUT 꺼짐, 또는 "내" 리스트에서 쫓겨났던 페이지 */
          pgbuf_lru_add_new_bcb_to_top (bcb, thread_private_lru_index);
          perfmon_inc (PSTAT_PB_UNFIX_VOID_TO_PRIVATE_TOP);
          pgbuf_bcb_register_hit_for_lru (bcb);
          return;
        }

      if (aout_list_id == PGBUF_AOUT_NOT_FOUND)
        {                                       /* 처음 보는 페이지 ⇒ scan resistance */
          pgbuf_lru_add_new_bcb_to_middle (bcb, thread_private_lru_index);
          perfmon_inc (PSTAT_PB_UNFIX_VOID_TO_PRIVATE_MID);
          pgbuf_bcb_register_hit_for_lru (bcb);
          return;
        }
      /* 남의 private 리스트에서 쫓겨났던 페이지 ⇒ shared로 내려간다 (fall through) */
    }

  /* ── 4단계: shared 리스트 middle ───────────────────────────── */
  pgbuf_lru_add_new_bcb_to_middle (bcb, pgbuf_get_shared_lru_index_for_add ());
  perfmon_inc (PSTAT_PB_UNFIX_VOID_TO_SHARED_MID);
  if (!PGBUF_VACUUM_SHOULD_IGNORE_UNFIX (thread_p))
    pgbuf_bcb_register_hit_for_lru (bcb);
}
경고 — 이 빌드에서 실제로 도달하는 경로 AOUT은 이 빌드에서 강제 비활성이다(§6.8.5). 따라서 aout_enabled는 항상 false이고 aout_list_id는 항상 PGBUF_AOUT_NOT_FOUND다. 결과적으로:
  • 3단계의 두 번째 조건 !aout_enabled가 항상 참 ⇒ private 리스트가 있는 스레드는 언제나 private TOP에 넣는다 page_buffer.c:6912-6919.
  • PSTAT_PB_UNFIX_VOID_TO_PRIVATE_MID 경로(middle 삽입)는 현재 도달 불가다 page_buffer.c:6921-6928. “처음 읽는 페이지는 middle에 넣어 scan resistance를 얻는다”는 설계는 실행되지 않는다.
  • 4단계 shared middle에 도달하는 경우는 private 리스트가 없는 스레드(세션이 없는 시스템 데몬, checkpoint, 비세션 워커)뿐이다 — 그리고 §6.6의 private→shared 이사.
SHOULD 재작성 시 결정 트리는 위 의사코드 그대로 구현한다. 도달 불가라고 생략하면 AOUT을 되살리는 순간(CBRD-20741 수정 시) 동작이 달라진다.

6.4.2 shared 리스트 라운드로빈 page_buffer.c:8937-9008

#define PAGE_ADD_REFRESH_STAT  MAX (2 * pgbuf_Pool.num_buffers / PGBUF_SHARED_LRU_COUNT, 10000)

int pgbuf_get_shared_lru_index_for_add (void)
{
  lru_idx = ATOMIC_INC_32 (&pgbuf_Pool.quota.add_shared_lru_idx, 1);   /* 전역 라운드로빈 카운터 */

  /* PAGE_ADD_REFRESH_STAT 호출마다 한 번, 전체 shared 리스트의 균형을 재평가한다 */
  if (lru_idx % PAGE_ADD_REFRESH_STAT == 0)
    {
      sum = 0; max_bcb = 0; min_bcb = pgbuf_Pool.num_buffers; idx_with_max = -1;
      for (i = 0; i < PGBUF_SHARED_LRU_COUNT; i++)
        {
          cnt = PGBUF_LRU_LIST_COUNT (PGBUF_GET_LRU_LIST (i));
          sum += cnt;
          if (cnt > max_bcb) { max_bcb = cnt; idx_with_max = i; }
          if (cnt < min_bcb) { min_bcb = cnt; }
        }

      if (sum > pgbuf_Pool.num_buffers / 10
          && (max_bcb > (int)(1.3f * sum) / PGBUF_SHARED_LRU_COUNT || max_bcb > 2 * min_bcb))
        {
          /* 한 리스트가 평균의 1.3배 이상이거나 최소의 2배 이상 ⇒ 그 리스트를 회피 대상으로 */
          ATOMIC_TAS_32 (&pgbuf_Pool.quota.avoid_shared_lru_idx, idx_with_max);
        }
      else
        {
          /* 불균형 해소됨: 회피 대상이 평균 이하로 내려왔으면 해제 */
          cur = pgbuf_Pool.quota.avoid_shared_lru_idx;
          if (cur == -1
              || PGBUF_LRU_LIST_COUNT (PGBUF_GET_LRU_LIST (cur)) < sum / PGBUF_SHARED_LRU_COUNT)
            ATOMIC_TAS_32 (&pgbuf_Pool.quota.avoid_shared_lru_idx, -1);
        }
    }

  lru_idx = lru_idx % PGBUF_SHARED_LRU_COUNT;

  /* 회피 대상에 걸리면 한 칸 더 돌린다 (한 번만) */
  if (pgbuf_Pool.quota.avoid_shared_lru_idx == (int) lru_idx)
    {
      lru_idx = ATOMIC_INC_32 (&pgbuf_Pool.quota.add_shared_lru_idx, 1);
      lru_idx = lru_idx % PGBUF_SHARED_LRU_COUNT;
    }
  return lru_idx;
}

6.6 private → shared 이사

이사는 “이 페이지는 한 세션의 것이 아니다”라는 판단이다. 조건은 두 개이며 OR다.

bool pgbuf_should_move_private_to_shared (bcb, int thread_private_lru_index)
{
  bcb_lru_idx = pgbuf_bcb_get_lru_index (bcb);

  if (PGBUF_IS_SHARED_LRU_INDEX (bcb_lru_idx))
    return false;                       /* 이미 shared다 */

  /* 조건 1: 이 BCB가 "내 것이 아닌" private 리스트에 있다
   *          ⇒ 두 개 이상의 세션이 이 페이지를 만졌다는 뜻 */
  if (thread_private_lru_index != bcb_lru_idx)
    return true;

  /* 조건 2: 내 리스트지만, 매우 뜨겁고 충분히 늙었다 */
  if (!pgbuf_bcb_is_hot (bcb))                                  return false;
  if (!PGBUF_IS_BCB_OLD_ENOUGH (bcb, PGBUF_GET_LRU_LIST (bcb_lru_idx))) return false;
  return true;
}

/* pgbuf_bcb_is_hot: fix 카운터가 포화 임계에 도달했는가 (page_buffer.c:16296-16301)
 *   count_fix_and_avoid_dealloc >= (PGBUF_FIX_COUNT_THRESHOLD << 16),  임계 = 64
 *   fix 카운터는 이 값에서 포화한다 (pgbuf_bcb_register_fix, 16275-16288) */

static void pgbuf_lru_move_from_private_to_shared (bcb)

#define MIN_PRIVATE_RATIO 0.01f

void pgbuf_adjust_quotas (void)
{
  quota = &pgbuf_Pool.quota; monitor = &pgbuf_Pool.monitor;

  /* ── 1) 재진입 가드 (mutex가 아니라 단순 플래그) ─────────────── */
  if (!PGBUF_PAGE_QUOTA_IS_ENABLED || quota->is_adjusting) return;
  quota->is_adjusting = 1;

  /* ── 2) 최소 간격 1 ms ─────────────────────────────────────── */
  tsc_getticks (&curr_tick);
  diff_usec = tsc_elapsed_utime (curr_tick, quota->last_adjust_time);
  if (diff_usec < 1000LL) { quota->is_adjusting = 0; return; }

  /* ── 3) 활동 임계: unfix 총량이 임계 미만이면서 500 ms도 안 지났으면 건너뛴다 ── */
  if (pgbuf_monitor_sum_pg_unfix (/*reset*/ false) < PGBUF_TRAN_THRESHOLD_ACTIVITY
      && diff_usec < 500000LL)
    { quota->is_adjusting = 0; return; }

  /* ── 4) 저활동 판정 + 누적 카운터 리셋 (reset=true) ──────────── */
  if (pgbuf_monitor_sum_pg_unfix (/*reset*/ true) < PGBUF_TRAN_THRESHOLD_ACTIVITY / 100)
    low_overall_activity = true;

  quota->last_adjust_time = curr_tick;

  /* ── 5) epoch 전진: 모든 BCB의 hit 자격을 재무장한다 ─────────── */
  ATOMIC_INC_32 (&quota->adjust_age, 1);

  /* ── 6) 리스트별 hits 수거 → 초당 환산 → private activity EMA ── */
  sum_private_activity = 0; private_hits = 0; shared_hits = 0; total_victims = 0;
  for (i = 0; i < PGBUF_TOTAL_LRU_COUNT; i++)
    {
      lru_hits = ATOMIC_TAS_32 (&monitor->lru_hits[i], 0);        /* 수거 겸 리셋 */
      lru_hits = (int) (1000000LL * lru_hits / diff_usec);        /* hits/sec */

      if (PGBUF_IS_PRIVATE_LRU_INDEX (i))
        {
          /* 10초 창의 지수이동평균. 10초 이상 지났으면 그냥 새 값으로 대체 */
          if (diff_usec >= 10000000LL)
            monitor->lru_activity[i] = lru_hits;
          else
            monitor->lru_activity[i] =
              (int) (((10000000LL - diff_usec) * monitor->lru_activity[i]
                      + diff_usec * lru_hits) / 10000000LL);

          sum_private_activity += monitor->lru_activity[i];
          private_hits += lru_hits;
        }
      else
        {
          shared_hits += lru_hits;
        }
      total_victims += PGBUF_GET_LRU_LIST (i)->count_vict_cand;   /* 무락 읽기 */
    }

  /* ── 7) private 비율 결정 + 클램프 + EMA ──────────────────── */

      private_ratio = MIN_PRIVATE_RATIO;          /* 0.01 — private을 거의 굶긴다 */
    }
  else
    {
      shared_hits   = MAX (1, shared_hits);       /* 0 나눗셈 회피 */
      private_ratio = (float) private_hits / (float) (private_hits + shared_hits);
      private_ratio = MIN (MAX_PRIVATE_RATIO, private_ratio);
      private_ratio = MAX (MIN_PRIVATE_RATIO, private_ratio);

  else

  else

      for (i = PGBUF_SHARED_LRU_COUNT; i < PGBUF_TOTAL_LRU_COUNT; i++)

                            ? (float) monitor->lru_activity[i] / (float) sum_private_activity
                            : 0.0f;

          lru_list->threshold_lru2 = (int) (new_quota * PGBUF_LRU_ZONE_MIN_RATIO);  /* 5% 고정 */

          /* ── 축소 메커니즘: zone 1+2가 quota를 넘으면 초과분을 zone 3으로 강등 ── */

        }

  shared_threshold_lru2 = (int) (avg_shared_lru_size * pgbuf_Pool.ratio_lru2);

  for (i = 0; i < PGBUF_SHARED_LRU_COUNT; i++)
    {
      lru_list = PGBUF_GET_LRU_LIST (i);
      lru_list->threshold_lru1 = shared_threshold_lru1;
      lru_list->threshold_lru2 = shared_threshold_lru2;

      if (PGBUF_LRU_ARE_ZONES_ONE_TWO_OVER_THRESHOLD (lru_list))
        {
          pthread_mutex_lock (&lru_list->mutex);
          pgbuf_lru_adjust_zones (lru_list, false);
          pthread_mutex_unlock (&lru_list->mutex);
        }
      if (lru_list->count_vict_cand > 0)          /* shared는 quota 조건 없이 항상 등록 */
        pgbuf_lfcq_add_lru_with_victims (lru_list);
    }

  /* ── 11) victim_rich 판정: 후보 총량이 풀의 10% 이상인가 ────── */
  pgbuf_Pool.monitor.victim_rich = (total_victims >= (int) (0.1 * pgbuf_Pool.num_buffers));

  quota->is_adjusting = 0;
}

6.10 수용 기준

수용 기준 A6 — 교체 정책 (마일스톤 M3) 아래는 quizzes/의 실측 시나리오다. 대응하는 정확한 수치는 10장의 quiz 기대치 표를 따른다.
  1. quiz 05 (eviction pressure) — 풀보다 작은 테이블을 한 세션이 전체 스캔할 때, victim이 자기 private 리스트에서 나와야 한다 (Num_victim_own_private_lru_success가 miss 수와 같은 자릿수). 2차 스캔의 I/O가 1차와 거의 같아야 한다 — “스캔이 자기 페이지를 자기가 쫓아낸다”. 게이지에서 Num_data_page_private_count > Num_data_page_private_quota가 관측되어야 한다 (quota는 hard limit이 아니라 soft target이다).
  2. quiz 06 (lru zones) — 정상 워크로드에서 Num_unfix_lru1_*_keep + Num_unfix_lru2_*_keep이 Num_unfix_lru{2,3}_*_to_top보다 훨씬 커야 한다. zone 1 to_top 카운터는 존재하지 않으며(구현상 boost가 없다), Num_unfix_lru1_*_to_top이 0이 아니면 N6-1 위반이다. 여러 세션이 같은 페이지를 뜨겁게 쓸 때 Num_unfix_lru*_private_to_shared_mid가 증가해야 하고, 역방향 카운터는 없어야 한다.
  3. quiz 08 (private vs shared) — 세션 B의 대량 스캔이 세션 A의 hot 페이지를 밀어내지 않아야 한다(3단계 Num_data_page_ioreads 델타 ≈ 0). 이는 §6.5의 세션 단위 격리와 §6.7의 quota가 함께 작동해야만 재현된다.
  4. AOUT 비활성 확인 — 어떤 워크로드에서도 Num_unfix_void_aout_found와 Num_unfix_void_to_private_mid가 0이어야 한다. 0이 아니면 §6.8.5의 강제 오버라이드를 재현하지 않은 것이다.
