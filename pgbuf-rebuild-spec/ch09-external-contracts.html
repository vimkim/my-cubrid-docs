9장 — 외부 모듈 계약

이 장의 범위 1~8장이 재작성 대상(page_buffer.c)을 규정했다면, 이 장은 재작성하지 않는 것을 규정한다. pgbuf는 log manager, Double Write Buffer, fileio, TDE, vacuum, session/thread, perfmon, system parameter의 여덟 모듈과 맞물려 있다. 재작성 코드는 이 모듈들의 소스를 건드리지 않고 기존 구현을 그대로 링크하므로, 여기서 고정해야 할 것은 구현이 아니라 호출 규약(calling contract)이다: 어떤 함수를 어떤 순서로, 어떤 락을 쥔 채/놓은 채, 어떤 반환값 해석으로 부르는가. 계약을 어기면 컴파일은 되지만 정합성이 깨진다 — 이 장의 MUST는 전부 그런 종류다.
읽는 방법 각 절은 (1) pgbuf가 부르는 함수와 (2) pgbuf를 부르는 진입점을 나누어 적는다. 방향이 반대인 계약을 섞으면 재작성 중 순환 의존을 만들기 쉽다. 예를 들어 checkpoint는 log manager가 pgbuf를 부르는 계약이고(9.1.4), WAL 강제는 pgbuf가 log manager를 부르는 계약이다(9.1.1). 두 방향의 순서 요구가 서로 다르다.

9.1 log manager 계약

9.1.1 WAL 강제: logpb_flush_log_for_wal

데이터 페이지 쓰기 직전에 반드시 호출되는 단 하나의 WAL 강제 지점이다.

void logpb_flush_log_for_wal (THREAD_ENTRY *thread_p, const LOG_LSA *lsa_ptr);
    /* src/transaction/log_page_buffer.c:4161-4189 */

의미론은 조건부 flush다. 내부는 다음과 같이 동작한다 log_page_buffer.c:4161-4189:

  1. logpb_need_wal (lsa_ptr)가 거짓이면 아무것도 하지 않고 즉시 반환한다.
  2. 참이면 PSTAT_LOG_NUM_WALS(statdump Num_log_wals)를 1 증가시킨다 log_page_buffer.c:4166.
  3. LOG_CS에 진입해 술어를 재평가하고(경합 중 다른 스레드가 이미 밀었을 수 있다), 여전히 참이면 logpb_flush_pages_direct로 동기 flush한다.

logpb_need_wal의 정의는 한 줄이다 log_page_buffer.c:11254-11267:

bool logpb_need_wal (const LOG_LSA *lsa)
{
  LOG_LSA nxio_lsa = log_Gl.append.get_nxio_lsa ();
  return LSA_LE (&nxio_lsa, lsa);           /* nxio_lsa ≤ lsa 이면 flush 필요 */

nxio_lsa는 "다음에 디스크로 나갈 로그 위치"다. 즉 lsa가 아직 디스크에 내려가지 않은 영역에 있으면 참이다. 이 술어는 락 없이 읽는 힌트이므로, pgbuf 쪽에서 값싼 사전 검사로 쓸 수 있다(victim flush 루프의 스킵 판정, 8장 참조) — 최종 보장은 LOG_CS 안의 재평가가 한다.

계약 N9-1 — WAL 순서 MUST BCB의 페이지 이미지를 디스크(또는 DWB)로 내보내기 전에, 그 BCB의 현재 페이지 LSA(iopage.prv.lsa)를 인자로 logpb_flush_log_for_wal을 호출해야 한다. 호출 판단 조건은 "oldest_unflush_lsa가 NULL이 아닐 것"이고, 전달 인자는 oldest_unflush_lsa가 아니라 현재 LSA다 page_buffer.c:10782-10795. 두 값을 혼동하면 WAL이 과소 강제된다.
MUST 이 호출은 BCB mutex를 놓은 상태에서 한다 page_buffer.c:10779-10787. log manager 내부에서 LOG_CS를 잡으므로 BCB mutex를 쥔 채 부르면 락 순서가 역전된다(4장 락 순서표).
SHOULD oldest_unflush_lsa가 NULL인데 페이지가 dirty인 경우 (로깅 없는 수정)는 정상 케이스로 취급하고, 임시 볼륨이 아니면 er_log_debug로만 남긴다 page_buffer.c:10797-10808.

MUST 이 세 변종(all / all_unfixed / all_unfixed_and_set_lsa_as_null)의 시그니처와 의미를 모두 유지할 것 — 외부 호출자가 이미 존재하므로 하나라도 빠지면 링크가 깨진다.

9.1.5 LOG_CS 보유 스레드의 토큰 면제

전제(pgbuf가 의존하는 외부 성질) flush rate 토큰 버킷(fileio_flush_control_get_token)은 LOG_CS를 보유한 스레드를 무조건 통과시킨다 — 토큰을 소모하지 않고 fc_Stats.num_log_pages에만 기록한 뒤 즉시 반환한다 file_io.c:771-774, file_io.c:808-812.
따라서 로그 flush는 데이터 페이지 rate limiter에 절대 걸리지 않는다. pgbuf의 WAL 강제가 토큰 고갈로 교착하지 않는 이유가 이것이다. 재작성자는 이 면제를 가정해도 된다. 반대로, pgbuf가 자체 rate limit을 추가하면서 WAL 경로를 그 안에 넣으면 이 성질이 깨져 데드락이 생긴다 — MUST NOT.

MUST SHOW 시점에만 전 샤드를 순회해 합산한다. 읽는 쪽도 락을 잡지 않으므로 값이 살짝 어긋날 수 있고, 그것이 계약이다.

(b) flushed 편향: Num_data_page_flushed는 victim flusher 전용이라 checkpoint flush는 0으로 잡힌다 page_buffer.c:4113.
