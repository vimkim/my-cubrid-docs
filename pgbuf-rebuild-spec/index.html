CUBRID pgbuf Rebuild Specification · 기준 소스 commit 5cd4f860e (branch pgbuf-analysis)

CUBRID Page Buffer 재구축 스펙

— 소스를 보지 않고 src/storage/page_buffer.c(17,500줄)를 처음부터 다시 구현하기 위한 규범(normative) 문서

이 문서의 목표 숙련된 C/C++ 시스템 프로그래머가 원본 소스를 열지 않고 이 책만으로 CUBRID 페이지 버퍼를 재작성해서, 기존 엔진에 drop-in으로 넣고 부팅·회귀 테스트·성능 특성이 같도록 만드는 것. 세미나 리포트(../pgbuf-analysis/cubrid-page-buffer-report_5cd4f860e_claude.html)가 "왜 이렇게 동작하는가"를 가르친다면, 이 책은 "정확히 무엇을 만들어야 하는가"를 규정한다.

0.1 충실도 원칙 (Fidelity Rules)

  • 규범 대상은 commit 5cd4f860e 시점의 이 트리다. 이 브랜치의 로컬 설계 (64-bit atomic latch word, per-thread 통계 샤딩 — CBRD-26941/26898/27041/27084/26975)를 포함한다. stock 11.5와 다른 지점은 본문에 표시한다.
  • 동작 충실(behavioral fidelity)이 기본값이다. 외부에서 관측 가능한 모든 동작 — API 의미론, 에러 코드, 카운터 증가 지점, 로그/디스크 쓰기 순서, 심지어 히트율 집계의 quirk까지 — 재현하는 것이 목표다. drop-in 검증이 가능해야 하기 때문이다.
  • 알려진 결함은 각주로 처리한다. 분석 중 발견된 결함 D1~D8 (../pgbuf-analysis/pgbuf-defects-report_5cd4f860e_claude.md)이 걸리는 지점마다 결함 각주 박스로 "충실 재현" vs "수정" 두 선택지를 명시한다. 기본 권장: 동작이 바뀌지 않는 결함(D2, D8)은 수정, 동작이 바뀌는 결함(D1, D3, D4)은 1차 구현에서 충실 재현 후 별도 커밋으로 수정.
  • 사문화 코드도 스펙이다. AOUT(강제 비활성), big-private 큐(생산자 없음), direct victim maintenance(no-op 루프)는 "현재 실행되지 않는다"는 사실까지 포함해 규정한다 — 재작성자가 이를 모르면 존재하지 않는 동작을 구현하느라 시간을 쓴다.

0.3 규범 용어 (Normative Language)

본문에서 MUST는 어기면 정합성/동시성이 깨지는 요구, SHOULD는 성능·운영상 강한 권장(어겨도 정확성은 유지), MAY는 재작성자의 재량을 뜻한다. 모든 규범 문장에는 근거 위치(page_buffer.c:NNNN, commit 5cd4f860e 기준)를 달아 검증 가능성을 유지한다 — 단, 재작성 자체에 그 소스를 볼 필요는 없도록 본문이 자기완결적으로 서술한다.

0.4 장 목록

  1. 요구사항과 외부 관점 — pgbuf가 엔진에 제공하는 보장, PAGE_PTR 의미론, 빌드 모드 3종, 스레딩 모델, 최상위 불변식 10
  2. Public API 계약 — 헤더가 내보내는 모든 진입점의 시그니처·사전/사후조건·에러·스레드 문맥 (계약 표 전체)
  3. 자료구조 스펙 — pgbuf_Pool 전 멤버, BCB 필드와 flags/latch 워드의 비트 배치, 해시·프레임·LRU·AOUT·direct victim 구조, 사이징 공식, 초기화 순서
  4. 동시성 프로토콜 — 락 인벤토리와 획득 순서, latch 부여 규칙 표, 무잠금 fast path의 안전 논증, 대기/기상 프로토콜, 타임아웃 정책, ordered_fix 순서 규약
  5. fix/unfix 알고리즘 — hit/miss/lockfree 경로, latch grant/block/wakeup, unfix 결정 트리, promote, ordered_fix — 전체 의사코드
  6. 교체 정책 — zone 전이 규칙, 리스트 연산, private/shared 배정, quota 조정 알고리즘, AOUT 스펙(비활성 각주 포함)
  7. victim 선택과 direct victim — 3단계 탐색, 리스트 스캔, lock-free 큐 프로토콜, 배급/소비/무효화, 기아 방지
  8. dirty·flush·checkpoint — LSA 규약, flush_with_wal, 데몬 4종, 토큰 버킷, victim 후보 flush, checkpoint seq flusher, flush_all 계열
  9. 외부 모듈 계약 — log/DWB/fileio/TDE/vacuum/ perfmon/시스템 파라미터: pgbuf가 호출하는 모든 외부 함수의 기대 계약과 전체 카운터·파라미터 표
  10. 구현 로드맵과 수용 검증 — 마일스톤 M0~M7, 불변식 런타임 체크, quizzes 12종을 수용 테스트로 쓰는 방법(기대 관측치), D1~D8 처리 방침
