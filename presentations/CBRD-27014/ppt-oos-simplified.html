CBRD-27014 · 01. Purpose & Background

OOS: 큰 컬럼을 분리해 작은 조회를 가볍게

스키마와 SQL은 그대로 두고, 큰 payload가 함께 있는 레코드에서 자주 쓰는 작은 값과 큰 값의 저장 위치를 분리한다.

문제 - 작은 조회에도 큰 값이 함께 움직인다

Record Header
id4B
statussmall
payload8KB

SELECT id, status 만 수행해도 payload가 든 heap page를 읽는다. 큰 값 때문에 페이지당 row 수가 줄어 buffer pool도 빨리 찬다.

목표 - 큰 payload를 자주 읽지 않는 workload에서 heap page I/O와 working set을 줄인다. 큰 값이 필요한 조회는 정확한 값과 기존 SQL 결과를 유지한다.
개선 기능큰 variable column을 table 전용 OOS file로 옮기고, heap에는 16B OOS OID만 남긴다.
개선 대상큰 레코드에서 작은 컬럼만 읽는 조회, heap page 밀도, buffer pool 효율
참고한 방식PostgreSQL TOAST의 column-level 분리와 largest-first 정책
적용 기준record가 DB_PAGESIZE/4를 넘을 때만 분리를 시작한다. 16KB page에서는 약 4KB다.

CBRD-27014 · 02. AS-IS / TO-BE

큰 레코드를 나누되, 애플리케이션에는 그대로 보이게

AS-IS heap record 안에 모든 값

HEAP PAGE

id
status
payload 8KB
id
status
payload 8KB

작은 값만 필요해도 payload가 차지한 heap page를 읽어야 한다.

레코드 데이터(recdes)가 하나의 DB page(보통 16KB)를 넘으면, 특수한 overflow page chain으로 옮겨 저장한다. overflow page 하나에는 recdes 하나만 들어가므로 큰 recdes 하나가 여러 16KB page를 점유하며, 남는 공간은 다른 레코드가 쓸 수 없어 내부 단편화가 커진다.

극단적인 나쁜 경우: overflow에 있는 4B int 하나만 읽어도 recdes 전체를 가져와야 한다. 연결된 모든 overflow page를 읽는 I/O가 발생한다.

TO-BE heap은 가볍게, payload는 OOS file로

HEAP PAGE

id
status
OOS OID16B
id
status
OOS OID16B
payload가 필요할 때만 ↓
OOS FILEpayload 8KB · payload 8KB · ...
1. 판단
record가 page의 1/4을 넘을 때만 OOS를 검토한다.
2. 분리
큰 variable column부터 하나씩 옮긴다.
3. 중단
record가 기준 아래로 내려오면 바로 멈춘다. 필요 이상으로 옮기지 않는다.

읽기 방식: 작은 컬럼 조회는 heap에서 끝나고, payload를 선택한 경우에만 lazy read로 OOS 값을 읽는다.
