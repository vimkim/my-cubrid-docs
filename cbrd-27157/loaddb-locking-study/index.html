Design review · 2026-08-12

Report 0001 — TT_LOADDB MVCCID self-lock 설계 검토

기초 자료를 읽은 뒤 보는 최신 보고서. 형규님의 uniform self-lock 의견을 소스에 대조하고, 성능 논거와 실제 분기 위치를 바로잡는다.

  • 답변 문장별 맞음·보완·불일치 판정
  • generic lock hot path와 self-lock helper 구분
  • uniform·common skip·assignment-only 세 안 비교
  • 현재 회귀 테스트 결과와 증거 경계
  • 회의에서 사용할 최종 권고 문장

보조 문서: 학습 범위와 성공 기준은 MISSION.md, 자료별 근거와 신뢰도는 RESOURCES.md에서 확인할 수 있다. 개념 학습만이 목적이라면 먼저 읽을 필요는 없다.

여기까지 설명하면 학습 완료다

  1. session transaction과 worker batch transaction이 각각 무엇을 소유하는가?
  2. BU_LOCK과 MVCCID self-lock은 key와 보호 목적이 어떻게 다른가?
  3. OOS file 생성은 왜 평소 loaddb가 가지 않던 self-lock 경로를 열었는가?
  4. early return과 assert 완화 중 무엇을 선택할지 결정하는 정책 질문은 무엇인가?

답이 막히면 해당 항목만 다시 읽는다. 답을 한두 문장으로 agent에게 보내면 resource, owner, observer와 invariant가 분리되어 있는지 피드백받을 수 있다.
