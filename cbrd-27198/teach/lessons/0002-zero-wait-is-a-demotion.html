Lesson 1 · Original failure

Zero-wait did not expire. It changed the request.

The tangible win: explain why the original failure was immediate even though the disk manager explicitly requested an unconditional latch.

One correction to the diagnostic: no transaction-lock attempt has to fail first. The transaction's wait-policy value is consulted directly inside the page-fix path.

The event chain

  1. Policy already equals zero.The transaction descriptor carries wait_msecs = LK_ZERO_WAIT, the value produced by lock_timeout=0.
  2. The caller asks for unconditional.The disk path calls pgbuf_fix(..., PGBUF_UNCONDITIONAL_LATCH) for a structural page.
  3. pgbuf_fix rewrites the condition.It reads the current transaction wait policy. Zero-wait changes UNCONDITIONAL to CONDITIONAL before trying the latch.
  4. The busy page cannot be latched immediately.The conditional branch rejects the request. It does not add the thread to the BCB wait queue.
  5. The fix returns failure now.For LK_ZERO_WAIT, the rejection sets ER_LK_PAGE_TIMEOUT and returns. A structural-page caller that assumes its unconditional fix cannot fail can then hit its assertion.

What happened

UNCONDITIONAL → CONDITIONAL → immediate rejection

What did not happen

enqueue → timed sleep → elapsed latch timeout

Read the decisive branches
