Lesson 1C · The ticket boundary

Reasonable policy, wrong place.

Immediate rejection is consistent with zero-wait in isolation. It is still wrong when zero-wait has crossed into a structural-page operation whose caller explicitly requires an unconditional fix.

User-level policy

lock_timeout=0: do not wait for conflicting logical transaction locks.

Internal requirement

PGBUF_UNCONDITIONAL_LATCH: obtain this short-lived structural-page latch even if it is temporarily busy.

The bug appears when the first policy silently rewrites the second request. The disk manager cannot treat “structural page was busy for an instant” as a normal result: it needs that page to maintain allocation metadata, and its unconditional-call contract was written on that assumption.

Therefore: the immediate rejection mechanism works as coded, but applying it to this structural-page fix violates the caller's contract.

The reviewed code labels the volume header a structural page and explicitly issues an unconditional fix. The generic page-buffer code performs the conflicting zero-wait demotion.
