## 보고서와 실패 분류

`my-cubrid-docs`에 공유 가능한 한국어 보고서를 작성한다. 완료 사항, 남은 일, 기술적 차단, 외부 승인 대기를 앞에 둔다. 기존 목록의 비CDC 후보 46행/35개 테스트를 출발점으로 모든 관련 실패와 새 증거를 반영한다. 공통 실패도 이름이 같다는 이유만으로 같은 증상으로 분류하지 않는다.

표에는 suite/테스트, 관측 증상, develop 비교, 원인 판단과 신뢰도, 처리 결정, 남은 일, 증거 링크를 담는다. 다음을 구분한다.

- 원인이 재현된 OOS 결함

- 검증된 테스트 기대값 또는 환경 차이
- 합의된 CDC 연기와 불완전한 suite 증거

원인 불명 또는 비교 미완료인 비CDC 항목은 머지 차단이다. 검증된 develop 기존 결함은 원칙적으로 이번 수정 범위에서 제외하되, 필수 체크나 OOS 데이터 안전성 검증을 막으면 차단을 유지한다. 차단 보고서를 완성하는 것과 기술적 준비를 완료하는 것은 별개다.

## 수정과 통합

현재 증거로 확인된 차단을 우선한다. Case18만으로 작업을 제한하지 않는다. 기존 통합 합의의 선행 기능 수정과 rollback/vacuum 데이터 손실 조건을 현재 코드와 회귀 증거로 재확인한다.

develop 동기화에는 실제 merge commit을 사용한다. 기능 수정은 집중된 검토 PR을 통해 통합하며 통합 브랜치 이력을 보존한다. 기존 리뷰의 구체적인 순서와 통합 방식은 현재 완료 상태에 맞춰 적용한다. 필요성이 검증된 테스트 수정은 논리적 검증을 유지하며 별도로 다룬다. 실패를 숨기기 위한 assertion 제거 또는 answer 교체는 허용하지 않는다.

과거 QA 배포 자산의 정확한 동일성을 아직 모르는 경우에도 버전을 고정한 로컬 원인 조사는 가능하다. 이를 전체 QA 동일성 또는 과거 QA 회귀의 재현 증명으로 표현하지 않는다. 기존 원본 증거와 참조 빌드를 보존하고, 빌드는 별도 worktree를 사용한다. R01은 기존 합의대로 필요한 원본 증거를 확보하기 전까지 증거 수집 단계로 유지한다.

## 최종 검증

검증 범위는 기존 Linux QA 전체 범위와 필수 PR CI다. 기존 QA 목록에서 suite와 release/debug 등 변형을 빠짐없이 나열하고, 현재 필수 체크와 대응시킨다. HA, 장시간 shell, CCI, JDBC, RQG 등도 자료 또는 실행 환경이 없다는 이유로 검증 범위에서 누락하지 않는다.

최종 통합 커밋, 테스트 버전, 실행기와 설정이 확인된 완료 결과는 재사용한다. 부족한 부분은 해당 suite의 지원되는 QA/CI 또는 개인 검증 절차로 추가 실행 대상으로 삼는다. 일부 focused 테스트의 성공은 전체 QA 성공을 대신하지 않는다. 과거에 승인된 S04 6회 실행은 이미 완료됐으며 다시 미완료로 취급하지 않는다.

변경 후 최종 head에 필요한 검증 근거가 유효한지 확인한다. 자료, 환경 또는 실행기 문제로 판정할 수 없는 항목은 차단으로 남기며, 진행 가능한 다른 항목을 계속 처리한다. 완료된 비교 결과와 증상 동등성을 근거로 기존 실패를 분류한다.

CDC의 `cbrd_27064`, `cbrd_27075`는 활성 상태로 실패가 보이게 유지한다. 이 두 건의 합의된 연기는 일반 비CDC 불확실성 차단과 구분한다. 실제 머지에는 해당 두 건만을 대상으로 한 maintainer/admin 예외가 필요하며, 그 확보 여부는 별도 승인 상태에 기록한다.
