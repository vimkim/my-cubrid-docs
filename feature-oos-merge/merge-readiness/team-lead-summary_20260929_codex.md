# OOS 진행 상황 요약

보고일: 2026년 9월 29일

**OOS는 기본 기능 구현과 일부 검증을 마쳤지만, 아직 develop에 병합할 단계는 아닙니다. 데이터 안전성 보완과 남은 테스트 실패 확인이 필요합니다. 최신 개발 코드와 테스트를 반영한 자동 회귀 테스트는 접수됐으며, 현재 결과를 기다리고 있습니다.**

OOS는 큰 데이터를 일반 행과 분리해 저장하는 기능입니다. 현재 작업의 목표는 기능이 동작하는 것을 넘어, 기존 기능과 함께 사용해도 데이터를 안전하게 유지하는지 확인하는 것입니다.

## 완료한 일

- 최신 개발 코드를 OOS 통합 브랜치에 반영했고, 두 빌드 방식에서 빌드와 구성된 단위 테스트를 모두 통과했습니다. 단위 테스트는 각각 35개입니다.
- 기존에 서버 종료가 관측된 동시 실행 테스트 한 건은 두 빌드 방식에서 모두 통과했습니다. 전체 문제가 해결됐다는 판정은 추가 확인 후 내립니다.
- 공개·비공개 테스트 저장소의 최신 변경을 통합하고, OOS 검증에 사용하는 테스트 브랜치와 동기화했습니다.
- 기존 QA 실패를 다시 모아, 확인된 사실과 원인 미확정 항목을 구분한 상세 보고서를 작성했습니다.

## 병합 전에 남은 일

1. **데이터 안전성 보완:** 저장·삭제 처리의 선행 수정과, 작업 취소 또는 정리 과정에서 필요한 데이터가 사라지지 않는지 확인해야 합니다.
2. **실패 원인 정리:** 남은 테스트 실패를 실제 OOS 결함, 기존 문제, 테스트 기대값·환경 차이로 구분하고 필요한 수정을 해야 합니다. 현재 발견된 실패를 모두 OOS 결함으로 판단한 상태는 아닙니다.
3. **최종 통합 검증:** 최신 코드와 테스트 조합으로 자동 회귀 테스트를 실행하고, HA·장시간 테스트 등 필요한 전체 QA 결과를 확보해야 합니다. 일부 테스트의 성공만으로 완료 처리하지 않습니다. OOS용 테스트 변경을 정식 테스트 브랜치에 반영하는 절차도 남아 있습니다.

## 다음 단계와 완료 판단

우선 최신 조합의 자동 회귀 테스트 결과를 확인하고, 선행 기능 수정과 데이터 안전성 검증을 진행합니다. 남은 실패의 원인을 설명할 수 있고 필요한 전체 검증이 끝났을 때 기술적 병합 준비 완료로 보고하겠습니다. 현재는 완료 일정을 확정할 근거가 부족합니다.

변경 데이터 추출 기능(CDC)의 두 실패는 합의된 연기 항목으로 별도 관리합니다. 실제 병합에는 이 두 건에 대한 담당자 예외 승인이 필요합니다.
