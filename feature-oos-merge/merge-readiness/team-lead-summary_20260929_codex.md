# OOS 진행 상황 요약

보고일: 2026년 9월 29일

**OOS는 기본 구현과 일부 검증을 마쳤지만, 데이터 안전성 보완과 전체 검증이 남아 있습니다. 기존 Manual QA 실패 139건 중 비CDC 비교 조사 후보는 48건이며, 그중 11건은 TC(테스트 케이스) 수정으로 해결될 가능성이 높습니다.**

OOS 코드 변경의 영향으로 볼 근거가 강한 것은 후보 48건 중 **3건**입니다. 이 3건은 위 TC 수정 예상 11건에 포함되며, 현재는 엔진 고장보다 오류 목록·저장 구조 변경에 따른 기대값 차이로 추정합니다.

## Manual test 결과

대상은 QA의 **RB-11.5.0-Manual, 11.5.0.2625-1ec35f8**이며, 비교 기준은 develop **11.5.0.2622-e1c3db1**입니다. 9월 29일 수집한 기존 빌드 결과이며, 이후 최신 코드를 반영한 새 빌드의 결과와 구분합니다.

| 테스트 항목 | 실패 | 그중 비CDC 비교 조사 후보 |
|---|---:|---:|
| SQL·medium·단위 테스트 | 0 | 0 |
| SQL-by-CCI | 11 | 2 |
| 일반 shell (release/debug) | 45 | 20 |
| 고부하·장시간 shell | 6 | 3 |
| CCI API (release/debug) | 3 | 2 |
| HA shell·복제 debug | 16 | 14 |
| 동시 실행 isolation (release/debug) | 3 | 3 |
| JDBC | 4 | 1 |
| 성능 shell | 3 | 2 |
| 무작위 SQL / vacuum (RQG) | 1 | 1 |
| CDC 복제 | 47 | 별도 관리 |
| **합계** | **139** | **48** |

여기서 후보는 **OOS 빌드에서만 실패가 식별됐거나 develop 비교 결과가 부족한 항목**입니다. OOS 결함 확정 건수가 아닙니다. 같은 테스트의 release/debug 실패는 각각 세었으며, 48건은 테스트 식별자 기준으로 37개입니다.

139건의 내역은 **비CDC 조사 후보 48건 + develop에서도 같은 이름으로 실패한 37건 + CDC 관련 51건 + 상세 식별자가 없는 장시간 shell 3건**입니다. CDC 51건은 위 표의 CDC 복제 47건과 일반 shell의 CDC 4건입니다. 공통 실패 37건도 증상이 같은지 추가 확인해야 합니다. HA 복제 release와 shell_ext는 결과가 없어 합계에 넣지 않았고, 장시간 shell 등 일부 결과도 미완료입니다.

## 원인은 무엇으로 보는가

아래는 **조사 후보 48건의 잠정 분류**입니다. CBRD 링크는 관련 기능·수정 또는 원본 테스트 이슈이며, 모두 OOS 원인으로 확정됐다는 뜻은 아닙니다.

| 나머지 | 25 | **원인 미확정** | HA 연결·복제·스키마, 시간 초과, 출력 순서, JVM 메모리, 성능·실행 타이밍 등을 조사해야 합니다. TC·환경·엔진 중 어느 쪽 수정인지 아직 정하지 않았습니다. |
| **합계** | **48** | | **이번 Manual QA 조사에서 OOS 엔진 결함으로 확정한 항목은 아직 없습니다.** |

**TC 수정으로 해결될 가능성이 높은 항목은 11건(3+8)입니다.** 이는 재실행으로 해결을 확인한 건수가 아닙니다. 나머지 중 9건(6+2+1)도 관련 TC 수정은 반영했지만, 기능 차이 또는 추가 원인 확인이 남아 있어 별도로 관리합니다. 답지를 바꿨다는 이유만으로 통과 처리하지 않습니다.

## 별도로 남아 있는 OOS 병합 조건

Manual QA 건수와 별개로, 기존에 등록된 OOS 수정 과제가 남아 있습니다. 위 48건에 중복해서 더하지 않습니다.

- **데이터 안전성 — 엔진 수정 필요:** 파티션 데이터의 소유 저장공간 불일치([CBRD-27089](http://jira.cubrid.org/browse/CBRD-27089))와, 취소된 UPDATE의 데이터를 vacuum이 삭제하는 문제([CBRD-27237](http://jira.cubrid.org/browse/CBRD-27237))를 해결·검증해야 합니다.
- **저장 정책 보완 — 엔진 수정 필요:** 변경 없는 값의 중복 저장 방지([CBRD-27230](http://jira.cubrid.org/browse/CBRD-27230)), 행 크기 목표와 여유 공간 정책 정리([CBRD-27057](http://jira.cubrid.org/browse/CBRD-27057))가 남아 있습니다.

## 현재까지의 진척과 다음 단계

최신 엔진과 두 테스트 저장소의 동기화·게시를 마쳤습니다. 로컬 단위 테스트는 **debug 35/35, release 35/35 통과**, 앞서 서버 종료가 관측된 isolation 사례는 **각 모드 1/1 통과**했습니다. 새 조합의 [전체 CI](https://github.com/CUBRID/cubrid/actions/runs/36570256001)를 요청했고, 위 Manual QA와 별도 결과로 확인합니다.

다음은 **새 테스트 결과 확인 → 데이터 안전성 수정 → 전체 QA 완료** 순서입니다. 기술적 준비 완료 시점은 남은 실패 원인과 검증 결과를 확인한 뒤 판단하겠습니다. CDC의 합의된 연기는 [CBRD-27064](http://jira.cubrid.org/browse/CBRD-27064)·[CBRD-27075](http://jira.cubrid.org/browse/CBRD-27075) 두 테스트에 한하며, CDC 관련 실패 51건 전체의 예외 승인을 뜻하지 않습니다.
